\section{Robust Black-Box DAG Combiner}
Intuitively, a robust black-box combiner for a primitive $\prim{P}$ that implements algorithms
$(\alg{Alg}{P}^1, \ldots, \alg{Alg}{P}^p)$ operates on $n$ candidate schemes by 
adaptively interleaving calls to the candidate oracles with ppt. processing, combining the candidate
outputs in a way that preserves the security properties of the secure subset of oracles,
provided there are sufficiently many. For certain arguments, it is helpful to model the combiner's
structure more explicitly. We do so by representing each algorithm implemented 
by the combiner as a directed acyclic graph (DAG) $\G$ that reflects the computation.

In addition to the DAG, we specify dedicated source and sink vertices $s$ and $t$, a vertex 
labeling $\ell: V(\G) \setminus \{s,t\} \to [n] \times [|\prim{P}|]$ that maps every non-source and non-sink
vertex to a tuple $(i,j)$ indicating which candidate is queried on which oracle, and a ppt. Turing machine 
$f^v$ for every vertex $v \in V(\G) \setminus \{s,t\}$ that computes the query input to the candidate and oracle
$\ell(v)$ given the oracle responses of the predecessors $\mathcal N_\G^-(v)$.
The source vertex $s$ corresponds to the input $\x$ to the algorithm, while the sink vertex $t$
is associated with a ppt. Turing machine $f^t$ that computes the final output $\y$ of the combiner.

A robust black-box DAG combiner algorithm is executed by tracing the computation through the corresponding DAG $\G$.
The input to each oracle query is computed from the responses of the oracles at preceding vertices using the Turing machine $f^v$ associated
with the respective vertex $v \in V(\G)$. The output of the algorithm is given by the output of $f^t$ on the collected inputs. We assume 
that the random tapes of the intermediate Turing machines are initialized identically to the random tape of the combiner Turing machine.

A robust black-box DAG combiner has to satisfy the requirements that the algorithm specified by the DAG description 
is a robust black-box combiner. We formally define robust black-box DAG combiners below. 

\begin{definition}[Robust $(n;k)$ Black-Box DAG P-Combiner]\label{def:robust_blackbox_dag_combiner}
	A robust $(n;k)$ black-box DAG combiner for a primitive P is a robust $(n;k)$ black-box combiner $\BBComb{P}$ in the sense of \Cref{def:robust_blackbox_combiner}, i.e., a tuple of algorithms $\Paren{\alg{Alg}{P}^1, \ldots, \alg{Alg}{P}^{p}}$
	where every algorithm $\alg{Alg}{P}$ is specified by a tuple of the following form
	\[
		\Paren*{\G, s, t, \ell, \Brace{f^{v}}_{v \in V(\G) \setminus \{s\}}}
	\]
	Here, $\G$ is a DAG, $s$ and $t$ are vertices in $V(\G)$
	such that $s$ has no incoming edges and $t$ has no outgoing edges,
	$\ell : V(\G) \to [n] \times [|\prim{P}|]$ is a vertex labeling and $\Brace{f^v}_{v \in V(\G) \setminus \{s\}}$
	are polynomial time Turing machines. Given this tuple,
	the algorithm $\alg{Alg}{P}$ is defined as shown in \Cref{fig:dag_combiner}.


	\begin{figure}[htbp]
		\centering 
		\begin{pchstack}[center, space=1em]
			\procedure[linenumbering]
			{Algorithm $\alg{Alg}{P}^{\O_1, \ldots, \O_n}(\x)$}
			{
				v_1, \ldots, v_m \gets \text{topological ordering of }V(\G) \setminus \{s,t\}\\
				\x_s \gets \x\\
				\pcfor i = 1 \text{ to }m \pcdo\\ 
				\t \pclinecomment{Compute the query $\mathbf q_{v_i}$ to the oracle}\\
				\t \mathbf q_{v_i} \gets f^{v_i}(\{(w, \x_w)\}_{w \in \mathcal N^-_{\G}(v_i)})\\ 
				\t \pclinecomment{Evaluate the oracle on $\mathbf q_{v_i}$}\\
				\t \x_{v_i} \gets \O_{\ell(v_i)}(\mathbf q_{v_i})\\ 
				\pcreturn f^t(\{w,\x_w\}_{w \in \mathcal N^-_{\G}(t)})
			}
		\end{pchstack}
		\caption{Definition of the robust black-box DAG combiner algorithm $\BBComb{P}[\O_1, \ldots, \O_n].\alg{Alg}{P}$ instantiated with candidates $\O_1, \ldots, \O_n$.
		We use the notation $\O_{\ell(v)}$ for $\ell(v) = (i,j)$ to denote the oracle algorithm $j$ of the $i$-th candidate $\O_i$, i.e., $\smash{\O_i.\alg{Alg}{P}^j}$.}
		\label{fig:dag_combiner}
	\end{figure}
\end{definition}

By definition, every robust black-box DAG combiner is a robust black-box combiner.
We also show that for every robust black-box combiner there exists a canonical robust black-box DAG combiner that is 
\textit{computationally equivalent}, in the sense that the implemented algorithms induce identical output distributions. 
We state this result formally in the following theorem, which allows us to conduct our impossibility proof for \Cref{thm:impossibility_21_comb}
over robust black-box DAG combiners rather than robust black-box combiners. 

\begin{restatable}[Robust $(n;k)$ Black-Box DAG Combiners]{theorem}{dagEquiv}\label{thm:generality_dag_comb}
	For every robust $(n;k)$ black-box combiner (\Cref{def:robust_blackbox_combiner}) there exists a computationally equivalent 
	robust $(n;k)$ black-box DAG combiner (\Cref{def:robust_blackbox_dag_combiner}).
\end{restatable}

\paragraph{Intuition.}
The idea behind the proof is to take an arbitrary robust $(n;k)$ black-box combiner $\BBComb{P}$
and unroll its computation into a graph consisting of $Q(n,\lambda)$ layers, where each vertex on layer $k$ is connected 
to all vertices of the preceding layers $i < k$. Each layer $k$ consists of $n|\prim{P}|$ vertices corresponding to the different oracles that 
can be queried as the $k$-th query. At every layer $k$, for every vertex, the combiner simulates the Turing machine 
of $\BBComb{P}$ until the $k$-th oracle query. Since the Turing machine $f^v$ cannot make any oracle queries itself, it relies on the preceding connected 
vertices to obtain the answer to those queries. For the $i$-th query, the Turing machine 
simply uses the output of the correct vertex on layer $i$ to simulate the oracle query. 
Once we reach the $k$-th query and we would make a query to oracle $\O_{(i,j)}$ then we distinguish two cases 
depending on whether $\ell(v) = (i,j)$.

If the current vertex satisfies $\ell(v) = (i,j)$, we return the query $\q_v$, resulting in the correct query being made.
Otherwise, if $\ell(v) \neq (i,j)$, we return an arbitrary query that meets the expected input format of $\O_{\ell(v)}$.
An important detail is that we must fix the random tape $\rho$ of the Turing machines $f^v$ for all $v \in V(\G) \setminus \{s\}$, 
since otherwise the executions may diverge when simulating oracle queries at later points. To address this, we can simply treat the Turing machines 
$f^v$ as deterministic with an additional input $\rho$ for the randomness. For notational simplicity, we leave this implicit in what follows.

\begin{proof}[\Cref{thm:generality_dag_comb}]
	Let $\BBComb{P}$ be a fixed robust $(n;k)$ black-box combiner for primitive $\prim{P}$,
	and let $\alg{Alg}{P}$ be an arbitrary algorithm implemented by $\BBComb{P}$.
	We label the candidate schemes $\O_1, \ldots, \O_n$.
	We construct a robust $(n;k)$ black-box DAG combiner $\DAGComb{P}$ that is computationally equivalent to $\BBComb{P}$.

	Since $\BBComb{P}$ is a robust $(n;k)$ black-box combiner, it is a ppt. Turing machine and the number of oracle queries made by 
	$\BBComb{P}$ is bounded from above by $Q \in \poly[n,\lambda]$. 
	We construct the DAG $\G$ for the robust black-box DAG combiner description of algorithm $\alg{Alg}{P}$ as follows:
	\begin{align}
		V(\G) &= \Brace*{s,t} \cup [Q(n,\lambda)] \times [n] \times [|\prim{P}|]\\ 
		E(\G) &= \Brace*{\bigl((d_1, i_1, j_1), (d_2, i_2, j_2)\bigr) \in [Q(n,\lambda)] \times [n] \times [|\prim{P}|]}\\ 
		&\quad \cup \{s\} \times [Q(n,\lambda)] \times [n] \times [|\prim{P}|]\\ 
		&\quad \cup [Q(n,\lambda)] \times [n] \times [|\prim{P}|] \times \{t\}
	\end{align}

	We define the vertex labeling $\ell(d,i,j) = (i,j)$ and the ppt. Turing machines $f^{v}$
	as follows. On input $\{(w,\x_w)_{w \in \mathcal N^-_{\G}(v)}\}$, simulate the Turing machine $\BBComb{P}.\alg{Alg}{P}$
	on the input $\x$. For every $q$-th query made to the oracle $(i,j)$, look up the values of $\x_{(q,i,j)}$ and continue execution with that oracle response.
	For the $k$-th query, if the query is to oracle $\ell(v)$, return the query. Otherwise,
	if the $k$-th query is to an oracle $(i,j) \neq \ell(v)$ return an arbitrary element in the domain of oracle $\ell(v)$ (this query will not be considered further in the execution).
	For $f^t$, simulate the entire execution of $\BBComb{P}.\alg{Alg}{P}$ analogously, but since no further queries are made, simply return the final result.

	To show that $\DAGComb{P}$ is a robust $(n;k)$ black-box DAG combiner, we need to show that the algorithm $\DAGComb{P}.\alg{Alg}{P}$
	specified by $(\G, s, t, \ell, \{f^v\}_{v \in V(\G)})$ is computationally equivalent to $\BBComb{P}.\alg{Alg}{P}$ and runs in time polynomial in $\lambda, n$.
	We first show that the algorithm is computationally equivalent.

	\begin{claim}\label{claim:correctness_dag_comb}
		Let $\BBComb{P}$ be a robust $(n;k)$ black-box combiner for primitive $\prim{P}$ (\Cref{def:robust_blackbox_combiner})
		and let $\DAGComb{P}$ be the combiner obtained by the procedure above. Then for all candidates $\O_1, \ldots, \O_n$
		and every algorithm $\alg{Alg}{P}$ implemented by $\BBComb{P}$ we have
		\[
			\BBComb{P}[\O_1, \ldots, \O_n].\alg{Alg}{P} \equiv \DAGComb{P}[\O_1, \ldots, \O_n].\alg{Alg}{P}
		\]
		Where $\equiv$ denotes equality of the output distributions.
	\end{claim}

	\begin{proof}[\Cref{claim:correctness_dag_comb}]
		Fix a robust $(n;k)$ black-box $\prim{P}$-combiner $\BBComb{P}$, candidate schemes $\O_1, \ldots, \O_n$
		and an algorithm $\alg{Alg}{P}$ implemented by $\BBComb{P}$. Let $\DAGComb{P}$ be the robust $(n;k)$ black-box DAG P-combiner 
		constructed as specified above, and let $\x$ be an arbitrary input to the algorithm $\alg{Alg}{P}$. We show that 
		\[
			\BBComb{P}[\O_1, \ldots, \O_n].\alg{Alg}{P}(\x) \equiv 
			\DAGComb{P}[\O_1, \ldots, \O_n].\alg{Alg}{P}(\x)
		\]
		We proceed by coupling the randomness of the execution of both algorithms on $\x$.
		Specifically, we use the same random tape for the combiner's internal computation in both $\BBComb{P}$
		and $\DAGComb{P}$ and for each query index $d$ and oracle $(i,j)$ we use the same random tape for every oracle response.
		Under this coupling, we show by induction on the number of queries that the outputs are identical.

		We say that a vertex $v$ on layer $d \in [Q(n,\lambda)]$ is \textit{correct}
		if in the execution of $\BBComb{P}[\O_1, \ldots, \O_n].\alg{Alg}{P}(\x)$ the $d$-th oracle query is 
		made to the oracle $\ell(v)$. We say that it is \textit{incorrect} otherwise.
		Formally, we show that for every $d \in [Q(n,\lambda)]$, the output of the $d$-th query of $\BBComb{P}[\O_1, \ldots, \O_n]$
		is equal to the output at the correct vertex on layer $d$ of $\DAGComb{P}[\O_1, \ldots, \O_n]$.
		We proceed by strong induction over $d$:

		\textit{Base case}: Let $d = 1$. The robust black-box DAG combiner $\DAGComb{P}[\O_1, \ldots, \O_n]$
			simulates $\smash{\BBComb{P}[\O_1, \ldots, \O_n]}$ until it reaches the first oracle query. Subsequently, it
			makes the same query $\q_v$ to the same oracle $\O_{\ell(v)}$ at the correct vertex $v$.
			Under the coupled randomness, the oracle responses are identical.

		\textit{Inductive step}: Assume that for all $d' < d$ the output of the correct vertex on layer 
		$d'$ is identical to the output of the $d'$-th oracle query in $\BBComb{P}[\O_1, \ldots, \O_n]$.
		Let $v$ be the correct vertex in layer $d$. The Turing machine $f^v$ simulates $\BBComb{P}.\alg{Alg}{P}$
		using the outputs of correct vertices on preceding layers to answer oracle queries. 
		By the induction hypothesis, these outputs match those of $\BBComb{P}[\O_1, \ldots, \O_n]$
		so $f^v$ computes the same query input $\q_v$. Since the vertex is correct, it queries the same oracle on the same input under the coupled randomness.
		Therefore, the responses are identical.
	\end{proof}

	\begin{claim}\label{claim:time_dag_comb}
		Let $\BBComb{P}$ be a robust $(n;k)$ black-box combiner for a primitive $\prim{P}$ (\Cref{def:robust_blackbox_combiner})
		and let $\DAGComb{P}$ be the combiner obtained by the procedure above. Then for all candidates $\O_1, \ldots, \O_n$,
		every algorithm $\alg{Alg}{P}$ implemented by $\DAGComb{P}[\O_1, \ldots, \O_n]$
		runs in time polynomial in $n$, $\lambda$ and the size of the input to $\alg{Alg}{P}$.
	\end{claim}

	\begin{proof}[\Cref{claim:time_dag_comb}]
		By construction, the DAG $\G$ has at most $2 + n \cdot |\prim{P}| \cdot Q(n,\lambda)$ vertices.
		Here, $Q(n,\lambda)$ is a polynomial upper bound on the number of queries of $\BBComb{P}.\alg{Alg}{P}$, where 
		we assume that $\prim{P}$ is constant.
		For every vertex $v \in V(\G)$, the Turing machine $f^v$ simulates $\BBComb{P}.\alg{Alg}{P}$.
		In this simulation every oracle query except the last one is answered with a constant-time lookup of the query response 
		in the predecessor outputs. The last query is made to a candidate oracle, also in constant-time.
		Therefore, the computation done at each vertex is bounded by $T(n,\lambda)$, where $T$
		is a polynomial bounding the runtime of $\BBComb{P}.\alg{Alg}{P}$ from above.
		The overall running time is bounded by the following expression.
		\[
			\bigl(2 + n\cdot|\prim{P}| \cdot Q(n,\lambda)\bigr) \cdot T(\lambda, n) \in \poly[\lambda, n]
		\]
	\end{proof}

	It remains to show that $\DAGComb{P}$ is a robust $(n;k)$ black-box combiner.
	By \Cref{claim:correctness_dag_comb}, the algorithms implemented by $\DAGComb{P}[\O_1, \ldots, \O_n]$
	and $\BBComb{P}[\O_1, \ldots, \O_n]$ have equivalent output distributions. In particular, any adversary $\A^{\O_1, \ldots, \O_n, \PSPACE}$
	against $\DAGComb{P}[\O_1, \ldots, \O_n]$ is also an adversary against $\BBComb{P}[\O_1, \ldots, \O_n]$
	with the same advantage. 
	Since $\BBComb{P}$ is a robust black-box combiner, by \Cref{def:robust_blackbox_combiner},
	there exist an injective function $\ell: [n-k+1] \to [n]$ and ppt. adversaries
	\[
		\B_1^{\O_{\ell(1)}}, \ldots, \B_{n-k+1}^{\O_{\ell(n-k+1)}}
	\]
	such that for any $i \in [n-k+1]$ the adversary $\B_i^{\O_{\ell(i)}}$ breaks the security of 
	the candidate $\O_{\ell(i)}$. Hence $\DAGComb{P}$ is a robust $(n;k)$ black-box combiner.
\end{proof}

\section{Impossibility of Robust Black-Box VRF-Combiner}

We consider the possibility of combining VRFs in a black-box fashion.
Specifically, we study robust $(2;1)$ black-box VRF-combiners. 
Such robust $(2;1)$ black-box VRF-combiners are conceptually the simplest robust black-box VRF-combiner.
Still, the existence of a robust $(2;1)$ black-box VRF-combiner immediately implies the 
existence of a robust $(n;1)$ black-box VRF combiner. On the other hand, an impossibility result implies 
that there exists no robust  $(n;\lfloor n/2\rfloor)$ black-box VRF-combiner.
Consequently, settling the $(2;1)$ case in either direction extends to a seemingly stronger result.

In this section, we prove the impossibility of a robust $(2;1)$ black-box VRF-combiner.
At a high level, the proof exploits the fact that the outputs of the candidate schemes must be used to produce a pseudorandom output,
yet they cannot influence the output distribution "too much". Otherwise, if a candidate has "too much" influence on the image, it could produce
two distinct images such that the verifier cannot detect which image was produced by the honest execution of the evaluation algorithm.

In the proof we make the simplifying assumption that the secret key space 
of all candidates is given by $\SK = \bin^{s(\lambda)}$ for a function $s \in \poly$.
We state the formal statement in the following theorem.

\begin{theorem}[Robust $(2;1)$ Black-Box VRF Combiner]\label{thm:impossibility_21_comb}
	There exists no robust $(2;1)$ black-box combiner (\Cref{def:robust_blackbox_combiner}) for the VRF primitive (\Cref{def:vrf}).
\end{theorem}

\paragraph{Intuition.}
Rather than proving the impossibility for robust $(2;1)$ black-box combiners directly, we prove the impossibility for 
robust $(2;1)$ black-box DAG combiners. The impossibility of a robust $(2;1)$ black-box VRF-combiner
then follows directly from the equivalence established in \Cref{thm:generality_dag_comb}.

Now suppose, for a contradiction, that there exists a robust $(2;1)$ black-box DAG VRF-combiner $\BBComb{VRF}$.
Let $\O_1, \O_2$ be candidate schemes, at least one of which implements a secure VRF.
By \Cref{def:robust_blackbox_combiner}, $\BBComb{VRF}[\O_1, \O_2]$ must implement a secure VRF. 
In particular, it must be perfectly correct 
and uniquely provable. We derive a contradiction by instantiating $\O_1,\O_2$
with specific candidate schemes at least one of which implements a secure VRF,
and then constructing an adversary $\A^{\PSPACE, \O_1,\O_2}$ that breaks the pseudorandomness of 
$\BBComb{VRF}[\O_1, \O_2]$ with non-negligible advantage.

The adversary works by iteratively narrowing down the set of candidate secret keys in the 
pseudorandomness experiment, starting with the secret key space $\SK$, using its PSPACE-complete
oracle $\PSPACE$. The filtering works as follows: $\A$ samples a polynomial number of evaluation points
$x_1, \ldots, x_{s(\lambda) + \lambda}$ u.a.r. from $\bin^\lambda$, then uses the evaluation oracle $\O_{\text{eval}}$
in the pseudorandomness security experiment to evaluate these points under the secret key $\sk^*$ in the security game to obtain image-proof pairs
$(y_1, \pi_1), \ldots, (y_{s(\lambda) + \lambda}, \pi_{s(\lambda) + \lambda})$.
Using public key $\pk^*$ of the security game, the adversary computes the trace of the combiner's verification algorithm on the tuples 
$(\pk^*, x_1, y_1, \pi_1),\ldots, (\pk^*, x_{s(\lambda) + \lambda}, y_{s(\lambda) + \lambda},\pi_{s(\lambda) + \lambda})$ to obtain 
$\tau_1, \ldots, \tau_{s(\lambda) + \lambda}$.
The key ingredient is a ppt. Turing machine $\alg{EvalSim}{VRF}$ that takes as input 
a tuple $(\sk,x_i,y_i,\pi_i,\tau_i)$ and returns either $\top$ or $\bot$, satisfying the following three properties:

\begin{itemize}
	\item $\alg{EvalSim}{VRF}$ makes no oracle queries to the candidates $\O_1, \O_2$
	\item If $\sk = \sk^*$ then $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \top$
	\item If $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x_i) \neq y_i$ then $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \bot$
\end{itemize}

Before elaborating on the construction of $\alg{EvalSim}{VRF}$, we first explain 
how the adversary can use this ppt. Turing machine to break the pseudorandomness of $\BBComb{VRF}[\O_1, \O_2]$.
Recall that we require the security properties of the combiner to hold relative to a PSPACE-complete oracle
precisely because we want the combiner to derive its security from the candidate oracles rather than implementing it itself.

$\alg{EvalSim}{VRF}$ makes no oracle queries, yet still only returns $\top$ only if a secret key candidate $\sk \in \SK$
\textit{agrees} with the game's secret key $\sk^*$ in the sense that on $x_i$, both evaluate to the same image.
Using its PSPACE-complete oracle $\PSPACE$, the adversary can enumerate the entire secret key space $\SK$
and discard any secret key candidate for which there exists a tuple $(x_i, y_i, \pi_i, \tau_i)$
such that $\alg{EvalSim}{VRF}$ returns $\bot$. (Strictly speaking, the $\PSPACE$ oracle decides membership queries for PSPACE languages,
we defer these technicalities to the formal proof.) Note that $\sk^*$ is never eliminated, since 
$\alg{EvalSim}{VRF}(\sk^*, x_i, y_i, \pi_i, \tau_i) = \top$ always holds and all surviving candidates evaluate to the same image 
as $\sk^*$ on $x_1, \ldots, x_{s(\lambda) + \lambda}$.
After filtering with every tuple $(x_i, y_i,\pi_i,\tau_i)$, two cases can arise:

If for sufficiently many tuples $(x_i,y_i,\pi_i,\tau_i)$ the number of eliminated candidate secret keys 
is sufficiently large, then after $s(\lambda) + \lambda$
iterations of filtering, we end up with a polynomially sized set $\SK_{cand}$ containing $\sk^*$.
The adversary can then sample a secret key $\sk_{cand} \sample \SK_{cand}$ uniformly at random.
If $\sk_{cand} = \sk^*$, the adversary wins the pseudorandomness security experiment. This happens with non-negligible probability.

On the other hand, if only for a small number of tuples $(x_i, y_i, \pi_i, \tau_i)$ set of candidate keys 
decreases significantly in size, then for many of the remaining candidates, the probability of evaluating a uniformly random evaluation point to the 
same image as $\sk^*$ has to be non-negligible.
In this scenario, the adversary proceeds analogously: It samples a uniformly random secret key candidate and 
evaluates the challenge input $x^*$ to compare it with the challenge image $y^*$.
Since $\sk_{cand}$ and $\sk^*$ evaluate $x^*$ to the same image $y^*$ with non-negligible probability, 
the adversary wins the game with non-negligible advantage.

We now describe the construction of the $\alg{EvalSim}{VRF}$ algorithm.
The algorithm simulates the evaluation of $\BBComb{VRF}[\O_1, \O_2]$ by iterating over the 
the vertices in $V(\G_{\textsf{Eval}})$ of the DAG corresponding to $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}$ in a fixed but arbitrary topological ordering.
At every vertex $v$ it simulates the associated Turing machine $f_{\textsf{Eval}}^v$ on the
corresponding inputs to obtain $\mathbf q_v$. 
Oracle queries to $\O_1$ are answered trivially with a fixed response,
this is the case as we will later initialize this oracle with a trivial, uniquely provable and perfectly 
correct oracle that returns fixed values for key generation and evaluation and verifies exactly the fixed image.
For oracle queries to $\O_2$ we distinguish \textit{exposed} queries, which can be read off the verification 
trace $\tau_i$, and \textit{obscure} queries, which are not contained in the verification trace.
The simulator answers the exposed queries with the response contained in $\tau_i$.
Thus the only queries that the simulator cannot perfectly answer are the obscure queries to $\O_2$.

For every obscure query to $\O_2$ the adversary branches its execution for every well-formed responses
of the query (e.g. all possible values in $\Y \times \P$ if the query is to $\O_2.\alg{Eval}{VRF}$) and
continues the execution for every branch. Finally if for all branches the evaluation of the combiner is $y_i$,
then $\alg{EvalSim}{VRF}$ returns $\top$, otherwise it returns $\bot$.
We illustrate the algorithm $\alg{EvalSim}{VRF}$ with pseudocode in \Cref{fig:eval_sim}.

It is easy to see that the first and third requirements for the $\alg{EvalSim}{VRF}$ algorithm are met.
By construction $\alg{EvalSim}{VRF}$ makes no oracle queries to candidates.
Assuming that $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x_i) \neq y_i$
then, since we answer all queries to $\O_1$ and the exposed queries to $\O_2$
truthfully, there must exist a well-formed assignment of oracle responses to 
obscure queries to candidate $\O_2$ such that the execution of 
$\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x_i)$ is simulated perfectly 
and therefore the output is not $y_i$, thus we have $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \bot$.

For the second property, we argue that for the security experiment's secret key $\sk^*$
any assignment of responses to obscure queries to candidate $\O_2$ does not change the image produced by the combiner simulation.
Suppose for a contradiction that there exists two different assignments of oracle responses that result in two different 
images $\tilde y \neq \hat y$. We derive a contradiction in three steps. First, we may assume without loss of generality that 
in the evaluation of the robust black-box DAG combiner's evaluation algorithm every specific oracle is queried on a specific input 
at most once (\Cref{claim:unique_queries}). Secondly, we construct two oracles $\widehat\O_2, \widetilde\O_2$, possibly not uniquely provable or perfectly correct, which are 
the oracle $\O_2$ remapped on the obscure queries to the two assignments that produce different images $\hat y \neq \tilde y$ respectively.
Third, we turn $\O_1$ into a full VRF by remapping all but a small subset of evaluation points to agree with the secure VRF $\O_2$ (\Cref{lemma:vrfification}).
Since $\widehat\O_2, \widetilde\O_2$ produce different images but only differ on obscure queries not contained in the verification trace 
they are indistinguishable for the combiner's verification algorithm. This forces the combiner to violate either unique provability or perfect correctness.
We show the description of the full adversary $\A$ in \Cref{fig:distinguisher}.

\paragraph{Formal Treatment.}
Let $\BBComb{VRF}$ be an arbitrary robust $(2;1)$ black-box DAG combiner for the VRF primitive.
Let $\O_{vrf}$ be a VF oracle implementing a secure VRF and let $\O_{uppc}$ be an oracle implementing 
a trivial, uniquely provable and perfectly correct VF such that the key generation algorithm always returns 
$(\sk_{def}, \pk_{def})$, the evaluation algorithm returns $(y_{def}, \pi_{def})$ for every input and 
the verification algorithm accepts a tuple $(\pk, x, y, \pi)$ if and only if $y = y_{def}$.
First, we show two important results that are central to the proof stated in \Cref{claim:unique_queries} and 
\Cref{lemma:vrfification}.

We claim that we can assume without loss of generality, that the robust black-box DAG combiner 
for the VRF primitive, during the execution of its evaluation algorithm on arbitrary inputs,
queries every oracle algorithm on any given input at most once.

\begin{claim}\label{claim:unique_queries}
	Let $\BBComb{VRF}$ be a robust $(n;k)$ black-box DAG VRF-combiner (\Cref{def:robust_blackbox_dag_combiner}). 
	There exists a robust $(n;k)$ black-box DAG VRF-combiner $\DAGComb{VRF}$ such that in the execution of the evaluation algorithm, 
	any oracle algorithm is queried on any given input at most once.
\end{claim}

\begin{proof}[\Cref{claim:unique_queries}]
	Let $\BBComb{VRF}$ be a robust $(n;k)$ black-box DAG VRF-combiner. We obtain $\DAGComb{VRF}$ by modifying $\BBComb{VRF}$
	in the following way: At every vertex $v \in V(\G_{\text{Eval}})$ the Turing machine $\tilde f_{\text{Eval}}^v$ maintains a table $T_v$
	of mappings from previous oracle queries $\q_w$ for $\smash{w \in \mathcal N^-_{\G_{\text{Eval}}}(v)}$ to oracle responses $\mathbf x_w$ of the same oracle algorithm $\ell_{eval}(v)$. $\widetilde f_{eval}^v$ 
	then simulates the Turing machine $f_{\text{Eval}}^v$ until it returns the query $\mathbf q_v$. Then $\widetilde f_{\text{Eval}}^v$ checks whether 
	$\q_w$ is contained in the table $T_v$. If that is not the case we issue the query $\q_w$ 
	to $\O_{\ell_{\text{Eval}}}(\mathbf q_w)$, otherwise we issue a fresh query $\widetilde \q_w$ not in the table.
	If the oracle is queried on $\widetilde\q_w$ subsequent Turing machines $f_{\text{Eval}}^u$ with $(v,u) \in E(\G_{\text{Eval}})$,
	will then simply find the first query to the oracle $\ell_{\text{Eval}}(v)$ with the same input if they are also incident to $u$.
	To ensure this, we will again simply draw an edge from the source to every other vertex, from every vertex $(d,i,j)$
	to any vertex $(d',i',j')$ if $d < d'$ and from every vertex to the sink.

	To show that $\DAGComb{VRF}$ is indeed a valid robust $(n;k)$ black-box DAG VRF-combiner it is sufficient to show that
	for any tuple of $n$ candidate schemes $\O_1, \ldots, \O_n$ of which at least $k$ implement a secure VRF the 
	algorithms implemented by $\BBComb{VRF}[\O_1, \ldots, \O_n]$ and $\DAGComb{VRF}[\O_1, \ldots, \O_n]$
	have equivalent output distributions. Since we do not modify the algorithms $\alg{Gen}{VRF}$ and $\alg{Vfy}{VRF}$, we only need to show that 
	equivalence holds for $\alg{Eval}{VRF}$.

	Assume towards a contradiction that this is not the case, i.e. that there exists an input $(\sk, x) \in \SK \times \bin^\lambda$
	such that $\BBComb{VRF}[\O_1, \ldots, \O_n].\alg{Eval}{VRF}(\sk, x) = y_1$ and $\DAGComb{VRF}[\O_1, \ldots, \O_n].\alg{Eval}{VRF}(\sk, x) = y_2$
	with $y_1 \neq y_2$. Since the Turing machines around the oracle calls are simulated the same way in both, this either means that $f^t_{eval}$
	is probabilistic or that an oracle query is answered differently and thus not deterministic. In both cases, both $y_1$ and $y_2$ could also have been produced 
	by $\BBComb{VRF}[\O_1, \ldots, \O_n]$. By perfect correctness both $y_1,y_2$
	must be verifiable but by unique provability only at most one of $y_1,y_2$ can be verifiable. A contradiction.
	We conclude that therefore the algorithm $\alg{Eval}{VRF}$ of $\BBComb{VRF}[\O_1, \ldots, \O_n]$ and $\DAGComb{VRF}[\O_1, \ldots, \O_n]$
	are functionally equivalent.

	It remains to show that $\DAGComb{VRF}[\O_1, \ldots, \O_n]$ runs in polynomial time. Observe that the number of vertices in $\G_{\text{Eval}}$
	remains unchanged from $\BBComb{VRF}[\O_1, \ldots, \O_n]$. Therefore, $|V(G_{\text{Eval}})| \in \poly[n, \lambda]$. At each vertex $v$,
	the Turing machine $\widetilde f_{\text{Eval}}^v$ performs the same computation as $f_{\text{Eval}}^v$ plus a table lookup in $T_v$.
	Since the size of the table is bounded from above by the number of vertices $|V(G_{\text{Eval}})|$ the lookup is efficiently computable.
	Hence, the overall running time of $\DAGComb{VRF}[\O_1, \ldots, \O_n]$ is bounded by a polynomial in $n$ and $\lambda$.
\end{proof}

From now on we will assume that for every input to the combiner's evaluation algorithm, 
an oracle is queried on any given input at most once. That is, if we remap the output of an oracle on a single point, 
then at most one oracle query differs in the execution of the evaluation algorithm for every input.

Next, let $\tildeSK \subseteq \SK$ and $\tildePK \subseteq \PK$ be sets
with size bounded by a polynomial, i.e. $\abs{\tildeSK}, \abs{\tildePK} \in \poly$.
We can construct an oracle $\widetilde\O_{uppc}$ from $\O_{vrf}$ and $\O_{uppc}$ such that 
$\widetilde\O_{uppc}$ implements a secure VRF and $\widetilde\O_{uppc}$ agrees with $\O_{uppc}$
on the outputs of the evaluation algorithm on all points $\widetilde\sk \in \tildeSK$
and on the verification algorithm on all points $\widetilde\pk \in \tildePK$.
Formally stated in the following lemma.

\begin{lemma}\label{lemma:vrfification}
	Let $\O_{vrf}$ be a VRF oracle (\Cref{def:vrf}) and $\O_{uppc}$ a VF oracle that is 
	perfectly correct (\Cref{def:correctness}) and uniquely provable (\Cref{def:unique_provability}).
	Let $\tildeSK \subseteq \SK$ and $\tildePK \subseteq \PK$ be polynomially bounded sets, i.e. 
	$|\tildeSK|, |\tildePK| \in \poly$. There exists an oracle $\widetilde\O_{uppc}$
	satisfying the following properties.
	\begin{enumerate}
		\item The evaluation algorithm of $\widetilde\O_{uppc}$ agrees with the evaluation algorithm of $\O_{uppc}$
			on all secret keys $\widetilde\sk\in\widetilde\SK$, i.e. we have that
			\[
				\forall \widetilde\sk \in \widetilde\SK, \widetilde\O_{uppc}.\alg{Eval}{VRF}(\sk, \cdot) = \O_{uppc}.\alg{Eval}{VRF}(\sk, \cdot)
			\]
		\item The verification algorithm of $\widetilde\O_{uppc}$ agrees with the verification algorithm of $\O_{uppc}$
			on all public keys $\widetilde\pk\in\widetilde\PK$, i.e. we have that
			\[
				\forall \widetilde\pk \in \widetilde\PK, \widetilde\O_{uppc}.\alg{Vfy}{VRF}(\pk, \cdot, \cdot, \cdot) = \O_{uppc}.\alg{Vfy}{VRF}(\pk, \cdot, \cdot, \cdot)
			\]
		\item The oracle $\widetilde\O_{uppc}$ implements a secure VRF (\Cref{def:vrf}).
	\end{enumerate}
\end{lemma}

A naive idea would be to replace the mapping of $\O_{vrf}.\alg{Eval}{VRF}$ on all inputs $(\sk, x)$
with $\sk \in \tildeSK$ and similarly modify the mapping of $\O_{vrf}.\alg{Vfy}{VRF}$ on all inputs $(\pk, x, y, \pi)$
with $\pk \in \tildePK$. However, the resulting oracle doesn't necessarily need to be uniquely provable or perfectly correct anymore.
For instance, imagine the scenario where a secret key $\widetilde\sk \in \tildeSK$ is remapped but the corresponding 
public key $\pk$ does not itself belong to $\tildePK$. In that case the verification algorithm on $\pk$ is left unchanged while the 
evaluation algorithm on $\widetilde\sk$ is modified. This can result in correctly computed image-proof pairs to be rejected by the verification 
algorithm, violating perfect correctness.

We begin by introducing two relations $\sim_\SK \subseteq \SK^2$ and 
$\sim_\PK \subseteq \PK^2$. Intuitively, these relations capture
whether two secret or public keys have a counterpart which could have been 
sampled with both keys. Formally, we define the relations $\sim_\SK, \sim_\PK$ as follows:
\begin{align}
	\sk_1 \sim_\SK \sk_2 &\iff \exists \pk \in \PK, \Prob*{
		\begin{aligned}
			(\sk_1, \pk) &\sample \O_{uppc}.\alg{Gen}{VRF}(1^\lambda) \; \land\\
			(\sk_2, \pk) &\sample \O_{uppc}.\alg{Gen}{VRF}(1^\lambda)
		\end{aligned}
	} > 0 \label{eq:sim_sk}\\ 
	\pk_1 \sim_\PK \pk_2 &\iff \exists \sk \in \SK, \Prob*{
		\begin{aligned}
			(\sk, \pk_1) &\sample \O_{uppc}.\alg{Gen}{VRF}(1^\lambda) \; \land\\
			(\sk, \pk_2) &\sample \O_{uppc}.\alg{Gen}{VRF}(1^\lambda)
		\end{aligned}
	} > 0 \label{eq:sim_pk}
\end{align}
We now consider the reflexive transitive closure of those relations $\sim_\SK^*, \sim_\PK^*$,
formally defined by $\sim^* = \bigcup_{k \in \N} \sim^k$. Since $\sim_\SK$ and $\sim_\PK$ are symmetric by definition, their 
reflexive transitive closures are reflexive, symmetric and transitive and hence equivalence relations. Given an element $\sk$,
we denote its equivalence class under $\sim_\SK^*$ with $[\sk]_{\sim_\SK^*} = \Brace{\sk' \in \SK : \sk' \sim_\SK^* \sk}$,
analogously for an element $\pk$ and the relation $\sim_\PK^*$ we define $[\pk]_{\sim_\PK^*} = \Brace{\pk' \in \PK: \pk' \sim_\PK^* \pk}$.

Additionally, for secret and public keys we define the function $R_\SK$ and $R_\PK$
respectively that map a key to all counterparts which are sampled with that key with non-negligible probability.
\begin{align}
	R_\PK(\pk) &= \Brace*{\sk\in\SK : \Prob*{(\sk, \pk) \sample \alg{Gen}{VRF}(1^\lambda)} > 0}\\ 
	R_\SK(\sk) &= \Brace*{\pk\in\PK : \Prob*{(\sk, \pk) \sample \alg{Gen}{VRF}(1^\lambda)} > 0}
\end{align}
Next, we define the notion of the closure of a set of secret or public keys.
Given a subset of secret keys $\widetilde\SK$ or public keys $\widetilde\PK$, we define its closure 
$\closure_\SK(\widetilde\SK)$ and $\closure_\PK(\widetilde\PK)$ which are just the union over the equivalence classes 
of all keys in the subsets. We formally define the functions as follows:
\begin{align}
	\closure_\SK(\widetilde\SK) &= \bigcup_{\widetilde \sk \in \widetilde\SK} [\widetilde\sk]_{\sim_\SK^*}\\ 
	\closure_\PK(\widetilde\PK) &= \bigcup_{\widetilde \pk \in \widetilde\PK} [\widetilde\pk]_{\sim_\PK^*} 
\end{align}
Observe that the secret key closure $\closure_\SK(\tildeSK)$ for a subset $\tildeSK \subseteq \SK$
is the set of secret keys that need to be remapped if we want to remap all of the evaluations on the 
secret keys $\tildeSK$ to preserve unique provability and correctness. The same holds for the public key closure.
Now we define the closure for subsets $\tildeSK \subseteq \SK$ and $\tildePK \subseteq \PK$
at the same time. They correspond to the minimal set of secret or public keys that need to be remapped to preserved 
unique provability and perfect correctness of $\O_{uppc}$ if we want to remap all keys in $\tildeSK$ and $\tildePK$.
\begin{align}
	\closure_\SK(\widetilde\SK,\widetilde\PK) &= \closure_\SK(\widetilde\SK) \cup \bigcup_{\widetilde\pk \in \closure_\PK(\widetilde\PK)} R_\PK(\widetilde\pk) \label{eq:closure_sk}\\ 
	\closure_\PK(\widetilde\SK, \widetilde\PK) &= \closure_\PK(\widetilde\PK) \cup \bigcup_{\widetilde\sk \in \closure_\SK(\widetilde\SK)} R_\SK(\widetilde\sk) 
\end{align}
Finally, we construct an oracle $\widetilde\O_{uppc}$ that interpolates between $\O_{uppc}$ and $\O_{vrf}$.
The key generation algorithm is defined to be the function for key generation of 
$\O_{vrf}$, the evaluation and the verification algorithm of $\widetilde\O_{uppc}$ are defined as follows:
They evaluate to the output of $\O_{uppc}$ on all keys in $\tildeSK$ and $\tildePK$
and they evaluate to the output of $\O_{vrf}$ otherwise.
\begin{align}
	\widetilde\O_{uppc}.\alg{Eval}{VRF}(\sk, x) &= \begin{cases}
		\O_{uppc}.\alg{Eval}{VRF}(\sk, x) & \text{if } \sk \in \closure_\SK(\widetilde\SK,\widetilde\PK)\\ 
		\O_{vrf}.\alg{Eval}{VRF}(\sk, x) & \text{otherwise}
	\end{cases}\label{eq:uppc_eval}\\ 
	\widetilde\O_{uppc}.\alg{Vfy}{VRF}(\pk, x, y, \pi) &= \begin{cases}
		\O_{uppc}.\alg{Vfy}{VRF}(\pk, x, y, \pi) & \text{if } \pk \in \closure_\PK(\widetilde\SK,\widetilde\PK)\\  
		\O_{vrf}.\alg{Vfy}{VRF}(\pk, x, y, \pi) & \text{otherwise}
	\end{cases}\label{eq:uppc_vfy}
\end{align}
The properties $1.$ and $2.$ of \Cref{lemma:vrfification} hold by definition of $\widetilde\O_{uppc}$
since $\tildeSK \subseteq \closure_\SK(\tildeSK) \subseteq \closure_\SK(\tildeSK, \tildePK)$
and $\tildePK \subseteq  \closure_\PK(\tildePK) \subseteq \closure_\PK(\tildeSK, \tildePK)$
which hold by reflexivity of $\sim_\SK^*$ and $\sim_\PK^*$ respectively.
We show that $3.$ holds by showing that $\widetilde\O_{uppc}$ is uniquely provable, perfectly correct 
and pseudorandom.

\begin{claim}\label{claim:vrfification_pc_up}
	Let $\O_{uppc}$ be a VF oracle that is uniquely provable (\Cref{def:unique_provability})
	and perfectly correct (\Cref{def:correctness}) and let $\O_{vrf}$
	be a VF oracle that implements a secure VRF (\Cref{def:vrf}).
	The oracle $\widetilde\O_{uppc}$ constructed from 
	$\O_{up}$ and $\O_{vrf}$ for given subsets $\tildeSK \subseteq \SK$ and $\tildePK \subseteq \PK$
	as in \eqref{eq:uppc_eval} and \eqref{eq:uppc_vfy}
	is perfectly correct (\Cref{def:correctness})
	and uniquely provable (\Cref{def:unique_provability}).
\end{claim}

Before we prove \Cref{claim:vrfification_pc_up} we claim that if a secret key $\sk$ can be sampled together with a public key $\pk$,
for any subset of secret keys $\tildeSK$ and any subset of public keys $\tildePK$, $\sk$ is in the closure of $\tildeSK$
if and only if $\pk$ is in the closure of $\tildePK$. Since the claim is intuitive and the proof is long we defer the proof to the appendix in \Cref{sec:sk_iff_pk}.

\begin{restatable}{claim}{skiffpk}\label{claim:sk_iff_pk}
	Let $(\sk, \pk) \sample \widetilde\O_{uppc}.\alg{Gen}{VRF}(1^\lambda)$ and $\tildeSK\subseteq \SK$ and $\tildePK \subseteq \PK$ be arbitrary subsets. Then
	the following holds:
	\[
		\sk \in \closure_\SK(\tildeSK,\tildePK) \iff \pk \in \closure_\PK(\tildeSK, \tildePK)
	\]	
\end{restatable}

\begin{proof}[\Cref{claim:vrfification_pc_up}]
	Let $\lambda \in \N$ be arbitrary but fixed.

	\textit{Correctness}: Let $(\sk, \pk) \sample \widetilde\O_{uppc}.\alg{Gen}{VRF}(1^\lambda)$,
	let $x \in \bin^\lambda$ be arbitrary and let $(y,\pi) \gets \widetilde\O_{uppc}.\alg{Eval}{VRF}(\sk, x)$.
	If $\sk \in \tildeSK$ then by \Cref{claim:sk_iff_pk} $\pk \in \tildePK$ and correctness holds by 
	the correctness of $\O_{uppc}$. Otherwise, if $\sk \notin \tildeSK$ then by \Cref{claim:sk_iff_pk} $\pk \notin \tildePK$
	and correctness holds by the correctness of $\O_{vrf}$.

	\textit{Unique Provability}: Assume towards a contradiction that there exist two image-proof pairs 
	$(y_1,\pi_1)$ and $(y_2, \pi_2)$ with distinct images $y_1 \neq y_2$ such that 
	$\widetilde\O_{uppc}.\alg{Vfy}{VRF}(\pk, x, y_1, \pi_1) = 1$ and $\widetilde\O_{uppc}.\alg{Vfy}{VRF}(\pk, x, y_2, \pi_2) = 1$.
	If $\pk \in \closure_\PK(\tildeSK, \tildePK)$ then verification is defined by $\O_{uppc}$ and we arrive at a contradiction 
	with the unique provability of $\O_{uppc}$. If $\pk \notin \closure_\PK(\tildeSK, \tildePK)$ then verification is defined by 
	$\O_{vrf}$ and therefore we arrive at a contradiction with the assumed unique provability of $\O_{vrf}$.
	In either case we reach a contradiction, hence there cannot exist such image-proof pairs.
\end{proof}

\begin{claim}\label{claim:vrfification_prf}
	Let $\O_{uppc}$ be a VF oracle that is uniquely provable (\Cref{def:unique_provability})
	and perfectly correct (\Cref{def:correctness}) and let $\O_{vrf}$
	be a VF oracle that implements a secure VRF (\Cref{def:vrf})
	that is $\errtime[prf][vrf]$-pseudorandom (\Cref{def:pseudorandomness}).
	The oracle $\widetilde\O_{uppc}$ constructed from 
	$\O_{up}$ and $\O_{vrf}$ for given subsets $\tildeSK \subseteq \SK$ and $\tildePK \subseteq \PK$
	as in \eqref{eq:uppc_eval} and \eqref{eq:uppc_vfy}
	is $\errtime[prf][uppc]$-pseudorandom (\Cref{def:pseudorandomness}).
	Where
	
	\[
		\err[prf][vrf] = \mu + \err[prf][uppc] \quad \text{ and } \quad \runtime[prf][vrf] = \runtime[prf][uppc]
	\]

	for $\mu \in \negl$. Therefore, if $\O_{vrf}$ is pseudorandom, then $\widetilde\O_{uppc}$ is pseudorandom.
\end{claim}

We prove the claim with a hybrid argument. Intuitively the proof works by bounding the probability that a bad event $\E$, that the 
secret key $\sk^*$ sampled in the pseudorandomness security experiment is in the set $\closure_\SK(\tildeSK, \tildePK)$.
If $\E$ doesn't occur, then the security game is identical to the security game against $\O_{vrf}$ which no adversary running in time
$\runtime[prf][vrf]$ wins with advantage greater than $\err[prf][vrf]$. Using the difference lemma we can then bound the advantage 
of any adversary playing the pseudorandomness game against $\widetilde\O_{uppc}$ from above by an expression 
in $\err[prf][vrf]$.

Equipped with \Cref{lemma:vrfification}, we now consider the combiner $\BBComb{VRF}$ initialized with the oracles
$\O_{vrf}$ and $\O_{up}$ as introduced above. We compute:
\begin{align*}
	x &\sample \bin^\lambda\\
	(\sk, \pk) &\sample \BBComb{VRF}[\O_{vrf}, \O_{up}].\alg{Gen}{VRF}(1^\lambda)\\
	(y,\pi) &\gets \BBComb{VRF}[\O_{vrf} \O_{up}].\alg{Eval}{VRF}(\sk, x)\\ 
	\tau &\gets \textsf{trace}\Paren*{\BBComb{VRF}[\O_{vrf}, \O_{up}].\alg{Vfy}{VRF}(\pk, x,y,\pi)}
\end{align*}
We classify the vertices of $V(\G_{\text{Eval}})$ as follows.
A vertex $v \in V(G_{\text{Eval}})$ is called \textit{exposed} if the oracle query issued at $v$ 
during the evaluation of the input $(\sk, x)$ also appears in the verification trace $\tau$.
Otherwise, we call $v$ \textit{obscure}.
Observe that exposed queries and queries to $\O_{uppc}$ can be answered without calling any oracle 
by looking at the verification trace or taking the default values $\sk_{def}, \pk_{def},y_{def},\pi_{def}, b_{def}$ respectively (where $b_{def}$ depends on the input $y$ to the verification).
The only queries whose responses are not directly available without any oracle queries are the obscure queries to $\O_{vrf}$.
We claim that these responses can be substituted with arbitrary, but well-formed, oracle responses without affecting the combiners output $(\sk, x)$.

\begin{claim}\label{claim:hidden_irrelevant}
	Let $\O_{vrf}$ and $\O_{uppc}$ be defined as above, let $\sk, \pk, x, y, \pi, \tau$ be defined as above and let 
	$V_{obs} \subseteq V(\G_{\text{Eval}})$ be the set of obscure vertices to $\O_{vrf}$.
	Then the oracles responses at vertices in $V_{obs}$ are irrelevant in the sense that 
	for any assignment of well-formed responses to the queries at vertices in $V_{obs}$
	the algorithm $\smash{\BBComb{VRF}[\O_{vrf}, \O_{uppc}].\alg{Eval}{VRF}}$ produces the same image $y$.
\end{claim}

\begin{proof}[\Cref{claim:hidden_irrelevant}]
Assume this were not the case, let $\widehat\O_{vrf}$ and $\widetilde\O_{vrf}$ be the oracles obtained from 
$\O_{vrf}$ by modifying the mapping on the obscure vertices $V_{obs}$ to the two assignments to obtain two different 
images $y_0\neq y_1$ and let $\widetilde\O_{uppc}$ be the VRF oracle obtained from $\O_{uppc}$ by applying the procedure 
detailed in \Cref{lemma:vrfification}.
Since $\widetilde\O_{uppc}$ is a secure VRF, the combiner initialized with the oracles $\widehat\O_{vrf}, \widetilde\O_{uppc}$ and the combiner 
initialized with the oracle $\widetilde\O_{vrf}, \widetilde\O_{uppc}$ must implement secure VRFs
and in particular also uniquely provable and perfectly correct VFs. Further note that by \Cref{claim:unique_queries}
we note that there can be no conflict of having to assign two different outputs to the query made to the same oracle on the same input 
at a different position since every oracle algorithm is queried at any input at most once. Hence:
\begin{align}
	\BBComb{VRF}[\widetilde\O_{vrf}, \widetilde\O_{uppc}].\alg{Vfy}{VRF}(\pk, x, \tilde y, \tilde\pi) = 1 \label{eq:correct}\\ 
	\BBComb{VRF}[\widehat\O_{vrf}, \widetilde\O_{uppc}].\alg{Vfy}{VRF}(\pk, x, \tilde y, \tilde\pi) = 0 \label{eq:unique_provability}
\end{align}
Since the oracle $\widehat\O_{vrf}$ and $\widetilde\O_{vrf}$ only differ on obscure queries we have that the verification algorithm 
on $(\pk, x, \tilde y, \tilde \pi)$ must evaluate the same and to the same result. This is a contradiction with 
\eqref{eq:correct} and \eqref{eq:unique_provability}.
\end{proof}

We define the evaluation simulation $\alg{EvalSim}{VRF}$ that simulates the evaluation 
without invoking any oracle queries. The simulation will simply traverse the evaluation algorithm 
of the DAG combiner. For any oracle query it checks the corresponding transcript $\tau_i$.
If the query is either to oracle $\O_1$ we can honestly answer it with $\x_v^{def}$ or in the transcript, 
then we can answer it honestly as well. If the query is \textit{obscure} then we branch once for every possible 
assignment of the oracle response which fits the given format, e.g. for a query to eval we branch 
for every answer $(y,\pi) \in \Y \times \P$. The pseudocode for $\alg{EvalSim}{VRF}$ is shown in \Cref{fig:eval_sim}.
In the following we show that this algorithm satisfies a few properties. We want to note that the evaluation simulation algorithm 
and is clearly inefficient since it enumerates possibly many well-formed oracle queries, since the adversary will use it only in combination 
with the PSPACE-complete oracle in the end that is not a problem.

\begin{claim}\label{claim:eval_sim}
	Let $\alg{EvalSim}{VRF}$ be the algorithm as described above and in \Cref{fig:eval_sim}

Now, we define two languages $\mathcal L_{cand}, \mathcal L_{size}$ as follows.
The language $\mathcal L_{cand}$ consists of tuples $(\rho, i, b, \{(x_i, y_i, \pi_i, \tau_i)\}_{i \in [s(\lambda) + \lambda]})$
containing the the bit $i$, the value of the bit $b$ of the $\rho$'th candidate key in the set after filtering the set of secret keys 
with the tuples $(x_i, y_i, \pi_i, \tau_i)$ for all $i \in [s(\lambda) + \lambda]$. We introduce the notation $\rank{\rho}{S}$
for $S\subseteq \bin^{s(\lambda)} = \SK$ and $\rho \in [|S|]$ to denote the $\rho$'th element in $S$ in canonical ordering.
The language $\mathcal L_{size}$ contains tuples $(m, \{(x_i, y_i, \pi_i, \tau_i)\}_{i \in [s(\lambda) + \lambda]})$ if 
$m$ is the size of the set of candidate keys after filtering with the tuples $(x_i, y_i, \pi_i, \tau_i)$ for all $i \in [s(\lambda) + \lambda]$.
\begin{align}
	\mathcal L_{cand} &:= \biggl\{
		\Paren*{\rho, i, b, \Brace*{\Paren*{x_i, y_i, \pi_i, \tau_i}}_{i \in [s(\lambda) + \lambda]}} : \notag\\
		&\qquad\qquad \rank{\rho}{\textstyle{\bigcap_{j \in [s(\lambda) + \lambda]}} \SK_{cand}(x_j, y_j, \pi_j, \tau_j)}_i = b
	\biggr\}\\[6pt]
		\mathcal L_{size} &:= \biggl\{
			\Paren*{m, \Brace*{\Paren*{x_i, y_i, \pi_i, \tau_i}}_{i \in [s(\lambda) + \lambda]}} : \notag\\
			&\qquad\qquad \abs*{\textstyle \bigcap_{j \in [s(\lambda) + \lambda]} \SK_{cand}(x_j, y_j, \pi_j, \tau_j)} \le m
		\biggr\}
\end{align}
We show that $\mathcal L_{cand}$ and $\mathcal L_{size}$ are in PSPACE and therefore membership can be decided by 
the PSPACE complete oracle. This will allow the adversary to decide membership 
using its PSPACE complete oracle.

\begin{claim}\label{claim:lang_pspace}
	$\mathcal L_{cand} \in \PSPACE$ and $\mathcal L_{size} \in \PSPACE$.
\end{claim}

\begin{proof}[\Cref{claim:lang_pspace}]
	We show membership in $\PSPACE$ by providing deterministic Turing machines $M_{cond}$ 
	and $M_{size}$ that decide $\mathcal L_{cond}$ and $\mathcal L_{size}$ respectively
	such that they require space polynomial in their input. Before we provide the Turing machines 
	$M_{cond}$ and $M_{size}$ we first show that $\alg{EvalSim}{VRF}$ can be executed in space polynomial  
	in the size of the input.

	To run $\alg{EvalSim}{VRF}$ in space polynomial in the input $(\sk, x, y, \pi, \tau)$
	we simulate the evaluation algorithm implemented by the combiner DAG. First compute the topological ordering 
	in polynomial space, then initialize a counter $c$ and simulate the combiner answering the obscure queries 
	with the tuple of assignments corresponding to the $c$'th element in the canonical on the tuple of well-formed assignments of the 
	obscure queries. That way we only need to store the values of all intermediate results and queries of a single combiner evaluation execution,
	since this execution runs in polynomial time, every iteration only requires polynomial space. 

	To show $\mathcal L_{cond} \in \PSPACE$ consider the following Turing machine $M_{cond}$.
	On input $(\rho, i, b, \{x_j, y_j, \pi_j, \tau_j\}_{j \in [s(\lambda) + \lambda]})$
	$M_{cond}$ starts by enumerating all secret keys $\sk \in \SK$ in lexicographic order. 
	For every $\sk$ iterate over every tuple $(x_j,y_j,\pi_j,\tau_j)$ over $j \in [s(\lambda) + \lambda]$ 
	and run $\alg{EvalSim}{VRF}(\sk, x_j, y_j,\pi_j,\tau_j)$.
	If the invocation returns $\bot$ discard the secret key and move onto the next onw. Otherwise after 
	we iterated over all $s(\lambda) + \lambda$ tuples increase a counter $c$ by one
	until $c = \rho$. If $c = \rho$ and $\alg{EvalSim}{VRF}(\sk, x_j, y_j,\pi_j,\tau_j) = \top$ then 
	look at the $i$'th bit $b'$ and accept if and only if $b' = b$. 

	To show $\mathcal L_{size} \in \PSPACE$ consider the following Turing machine $M_{size}$.
	On input $(m, \{x_j, y_j, \pi_j, \tau_j\}_{j \in [s(\lambda) + \lambda]})$ $M_{cond}$
	proceeds in a similar fashion to $M_{cond}$.
	$M_{soze}$ starts by enumerating all secret keys $\sk \in \SK$ in lexicographic order,
	for every $\sk$ we iterate over the tuples $(x_j,y_j,\pi_j,\tau_j)$ for $j \in [s(\lambda) + \lambda]$
	and run and run $\alg{EvalSim}{VRF}(\sk, x_j, y_j,\pi_j,\tau_j)$.
	If the invocation returns $\bot$ discard the secret key and move onto the next one.
	Otherwise after 
	we iterated over all $s(\lambda) + \lambda$ tuples increase a counter $c$ by one.
	After all secret keys return $c$.
\end{proof}

We now describe the adversary $\A$ that wins the pseudorandomness security experiment 
against the combiner initialized with oracles $\O_{vrf}$ and $\O_{uppc}$ with non-negligible advantage.
First, $\A$ first samples $s(\lambda) + \lambda$ evaluation points uniformly at random $x_1, \ldots, x_{s(\lambda) + \lambda}$.
Subsequently, $\A$ uses the evaluation oracle in the prf game to evaluate the points to obtain 
$(y_1, \pi_1), \ldots, (y_{s(\lambda) + \lambda}, \pi_{s(\lambda) + \lambda})$. Using the public key $\pk^*$
the adversary will then compute the combiner's verifier traces for all tuples consisting of evaluation point and image-proof pair

of the candidate key set, $k$, by querying the $\PSPACE$ oracle to decide membership in $\mathcal L_{size}$ before 
sampling a random element $\rho \sample [k]$ and recovering the $\rho$'th candidate $\sk_{cand}$ bit-by-bit using the PSAPCE-complete oracle 
to decide membership in $\mathcal L_{cand}$.

obtain from the challenger the challenge image $y^*$, computes the image $y'$ of $x^*$ under the combiner's evaluation algorithm 
with the secret key candidate $\sk_{cand}$ and guesses bit $b = 0$ if and only if $y' = y^*$.

\begin{proof}[\Cref{claim:advantage_distinguisher}]
	\textit{Runtime}: The adversary $\A$ can sample $s(\lambda) + \lambda$ evaluation points,
	query the games evaluation oracle on them to obtain the image-proof pairs and 
	evaluate the combiner's verification algorithm on the point-image-proof tuples to obtain the trace in time $\O(s(\lambda) + \lambda)$.
	The set of candidate keys is bounded in size by the size of the secret key space, thus by means of binary search $\A$
	can obtain the size with at most $s(\lambda)$ queries to the PSPACE complete oracle.
	With another $s(\lambda)$ queries $\A$ can then recover the $\rho$'th candidate key
	bit-by-bit. The final evaluation of the combiner's evaluation algorithm on the candidate secret key and the challenge pre-image
	can also be done in polynomial time due to the efficiency requirement on the robust black-box DAG combiners.
	Overall, the adversary runs in time polynomial in $\lambda$ and $n$.

	\textit{Advantage}: During its execution, $\A$ will correctly compute the size of the candidate key set,
	then obtain a uniformly random candidate secret key. We invoke \Cref{claim:candidate_likely_good}
	which yields that with probability at least $\tfrac{1}{2} - \tfrac{1}{2^{\lambda + 1}}$ the candidate secret key 
	will evaluate to the same image on the challenge pre-image $x^*$ as the games internal secret key would.
	Therefore, with probability at least $\tfrac{1}{2} - \tfrac{1}{2^{\lambda + 1}}$ $\A$ wins the game.
	Otherwise, with probability at most $\frac{1}{2} + \tfrac{1}{2^{\lambda + 1}}$ the adversary will not obtain the correct 
	image $y^*$. If the hidden bit $b = 0$ then the adversary loses since he will guess $b = 1$, if the hidden bit 
	is $b = 1$ then he will win except if the output $y' = y^*$ by chance. Since $y$ is in that case sampled u.a.r. 
	we can bound the probability of that happening with $1-\tfrac{1}{|\Y|}$. Overall we get:

	\begin{align}
		\Adv{\BBComb{VRF}[\O_{vrf}, \O_{up}]}{prf}{\lambda, \A}

		&= \abs*{\frac{1}{|\Y|} - \frac{1}{2} + \frac{1}{2^{\lambda + 1}}}\\

Using \Cref{claim:advantage_distinguisher} we can now finally prove the \Cref{thm:impossibility_21_comb}.

\begin{proof}[\Cref{thm:impossibility_21_comb}]
	\Cref{claim:advantage_distinguisher} states that for every robust $(2;1)$ black-box DAG VRF-combiner $\BBComb{VRF}$ 
	there exists a polynomial time adversary $\A$ with non-negligible advantage against $\BBComb{VRF}$ initialized with 
	candidates $\O_{vrf}$ and $\O_{up}$. Since $\O_{vrf}$ implements a secure VRF we conclude that there exists no
	robust $(2;1)$ black-box DAG VRF combiner since there exists no polynomial time adversary $\mathcal B$ against $\O_{vrf}$.
	Since there exists no robust $(2;1)$ black-box DAG VRF-combiner, by \Cref{thm:generality_dag_comb}, there also 
	doesn't exist a robust $(2;1)$ black-box VRF-combiner.
\end{proof}

While robust $(2;1)$ black-box combiners are generally sufficient to construct robust $(n;1)$ black-box combiners,
non-existence of a robust $(2;1)$ black-box combiner 
only allows one to deduce the impossibility of a robust $(n;\lfloor n/2\rfloor)$ black-box combiner.
This allows us to extend the result in \Cref{thm:impossibility_21_comb} to an infinite family of robust black-box VRF-combiners.

\begin{lemma}[Robust $(n; \lfloor n/2\rfloor)$ Black-Box VRF Combiner]\label{lemma:nhalf}
	There exists no robust $(n; \lfloor n/2\rfloor)$ black-box combiner in the sense of \Cref{def:robust_blackbox_combiner} for the VRF primitive 
	defined in \Cref{def:vrf} for all $n \in \N^+$.
\end{lemma}

\begin{proof}[\Cref{lemma:nhalf}]
	We show how to construct a robust $(2;1)$ black-box VRF-combiner $\DAGComb{VRF}$ from a robust $(n;\lfloor n/2\rfloor)$ black-box VRF-combiner $\BBComb{VRF}$.
	The result holds by contraposition of this fact applied to \Cref{thm:impossibility_21_comb}.
	$\DAGComb{VRF}$ is simply $\BBComb{VRF}$ but the first $\lfloor n/2\rfloor$ candidates are initialized with $\O_1$
	and the other $\lceil n/2\rceil$ candidates are initialized with $\O_2$. If either $\O_1$ or $\O_2$
	implements a secure VRF then at least $\lfloor n/2\rfloor$ candidates used to initialize $\BBComb{VRF}$ are secure,
	the initialized combiner is secure. 
\end{proof}

Extending this result to an impossibility of robust $(n;n-1)$ turned out to be more difficult than expected. 
While the proof for \Cref{thm:impossibility_21_comb} doesn't seem to generalize to an impossibility result for 
robust $(n;n-1)$ robust black-box VRF-combiner we still believe that such constructions can be proven to be impossible.
We state the result as a conjecture and defer to the appendix for a discussion on why the approaches don't easily generalize.

\begin{conjecture}
	There exists no robust $(n;n-1)$ black-box combiner in the sense of \Cref{def:robust_blackbox_combiner} for the VRF primitive 
	as defined in \Cref{def:vrf} for all positive natural numbers $n \in \N^+$.
\end{conjecture}

Finally we want to note that the adversary constructed in the proof of \Cref{thm:impossibility_21_comb}
can predict the image of any arbitrary pre-image $x \in \bin^\lambda$. This means that the adversary is strong enough
win the weak pseudorandomness and unpredictability security experiment with the same advantage as in \Cref{claim:advantage_distinguisher}.
As a corollary of \Cref{thm:impossibility_21_comb}, we get the impossibility of robust $(n;\lfloor n/2\rfloor)$
black-box combiners for the VUF and WVRF primitive. 

\begin{corollary}[Robust $(n;\lfloor n/2\rfloor)$ Black-Box $\prim{VUF}$-combiner]\label{cor:impossibility_vrf_comb}
	There exists no robust $(n;\lfloor n/2\rfloor)$ black-box combiner in the sense of \Cref{def:robust_blackbox_combiner}
	for the VUF primitive as defined in \Cref{def:vuf}.
\end{corollary}

\begin{corollary}[Robust $(n;\lfloor n/2\rfloor)$ Black-Box $\prim{WVRF}$-combiner]\label{cor:impossibility_vuf_comb}
	There exists no robust $(n;\lfloor n/2\rfloor)$ black-box combiner in the sense of \Cref{def:robust_blackbox_combiner}
	for the WVRF primitive as defined in \Cref{def:wvrf}.
\end{corollary}

\section{Relaxed Robust Black-Box VRF-Combiners}

In the previous section we established an impossibility of robust $(n;\lfloor n/2\rfloor)$ black-box combiners for the 
VRF, WVRF and VUF primitives and conjectured that the result extends to robust $(n;n-1)$ black-box combiners.
A natural follow-up question is whether the impossibility results can be circumvented by relaxing by either strengthening by introducing 
additional assumptions on the candidates. In this section, we show that under the additional assumption that all candidates 
satisfy unique provability and perfect correctness, there exist simple robust $(n;1)$ black-box combiners for VRFs.

We argue that the additional assumptions are reasonable in practice.
Since perfect correctness and unique provability are information theoretic properties they don't rely on 
computational hardness assumptions but can generally be proved rigorously.
As a result, for concrete VRF constructions that satisfy those properties, the guarantee holds 
regardless of advances in cryptography and therefore there is no reason to hedge against them by using combiners.

As already mentioned in \Cref{sec:intro_prf_combiners}, PRFs admit a simple robust $(n;1)$ black-box combiner
which simply XORs the outputs of all PRF candidates. We show that this construction 
can be extended to VRFs by simply computing the transcript of the evaluation algorithms 
and providing this as a proof. 

\begin{lemma}[Relaxed Robust $(n;1)$ Black-Box VRF Combiners]\label{lemma:strong_robust_black_box_combiners}
	There exist robust $(n;1)$ black-box combiners in the sense of \Cref{def:robust_blackbox_combiner}
	for the VRF primitive \Cref{def:vrf} if we assume that all candidates are uniquely provable in the sense of \Cref{def:unique_provability}
	and perfectly correct in the sense of \Cref{def:correctness}.
\end{lemma}

% \begin{proof}[\Cref{lemma:strong_robust_black_box_combiners}]

We construct a robust $(2;1)$ black-box VRF-combiner under the assumption that all 
candidates are perfectly correct and uniquely provable. A robust $(n;1)$ black-box VRF-combiner 
can then be constructed by iteratively applying the construction, combining the previous combiner's output 
with the next candidate oracle until all $n$ candidate schemes are incorporated.

The construction, illustrated in \Cref{fig:vrf_comb}, closely follows the construction of the robust 
$(2;1)$ black-box PRF-combiner in \Cref{fig:prf_comb}.
The key generation algorithm samples a key pair per candidate and combines the secret and public keys to 
form the combined key pair. The evaluation algorithm evaluates the point $x$ with both candidate schemes
to obtain $(y_1, \pi_1)$ and $(y_2, \pi_2)$. The image is then $y = y_1 \xor y_2$ with the proof being 
$\pi = (y_1, \pi_1, y_2, \pi_2)$.
The verification algorithm works by first checking whether both values $y_1, y_2$ with proof $\pi_1, \pi_2$ in the proof 
verify under the verification algorithm of the respective candidate 
and secondly checks whether $y = y_1 \xor y_2$.

\begin{claim}\label{claim:pc_up_vrf_comb}
	The combiner in \Cref{fig:vrf_comb} is perfectly correct in the sense of \Cref{def:correctness}
	and uniquely provable in the sense of \Cref{def:unique_provability} if all candidates
	are perfectly correct \Cref{def:correctness} and uniquely provable \Cref{def:unique_provability}.
\end{claim}

\begin{proof}[\Cref{claim:pc_up_vrf_comb}]
	\textit{Correctness:} Since both $\O_1$ and $\O_2$ are assumed to be correct the images $(y_1, \pi_1)$ and $(y_2, \pi_2)$
	must correctly verify. By construction of the combiner $y = y_1 \xor y_2$ and therefore the combiner verification verifies.

	\textit{Unique Provability:} 
	Assume towards a contradiction that there exist image-proof pairs $(y_1, \pi_1)$ and $(y_2, \pi_2)$ with $y_1 \neq y_2$ such that both verify under 
	a shared public key $\pk$. By construction we know $y_1 = y_{11} \xor y_{12}$ and $y_2 = y_{21} \xor y_{22}$. Since $y_1 \neq y_2$
	we have that $(y_{11}, y_{12}) \neq (y_{21}, y_{22})$, w.l.o.g. let $y_{11} \neq y_{21}$. Since both $(y_1, \pi_1)$ and $(y_2, \pi_2)$
	verify however, by construction of the combiner, there must exist $\pi_{11}$ and $\pi_{21}$ such that the verification algorithm of $\O_1$
	both accepts $(y_{11}, \pi_{11})$ and $(y_{21}, \pi_{21})$ which is a contradiction as we assumed all candidates to be uniquely provable.
\end{proof}
