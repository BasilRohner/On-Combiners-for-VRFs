\section{Robust Black-Box DAG Combiner}
Intuitively, a robust black-box combiner operates on $n$ candidate schemes by 
adaptively interleaving calls to the candidates oracles with ppt. processing
to combine the candidates outputs in a way such that security properties of the secure 
subset of oracles are preserved if there are sufficiently many of them.
For certain arguments it can be helpful to model the combiners structure more explicitly,
we do so by modeling every algorithm implemented by the combiner with a directed acyclic graph (DAG) reflecting the computation.

In addition to the DAG we specify dedicate source and sink vertices $s$ and $t$,
a vertex labling $\ell : V(\G) \setminus \{s,t\} \to [n] \times [|\prim{P}|]$ mapping every non-source and non-sink vertex to a tuple $(i,j)$
indicating which candidate is queried on which oracle and ppt. Turing machines $f^v$ for every vertex $v \in V(\G)$
that compute the query input to the candidate and oracle $\ell(v)$ given the oracle response of the predecessors $\mathcal N^-_\G(v)$.
The source vertex $s$ simply corresponds to the input $\x$ to the algorithm while the target
is associated with a single ppt. Turing machine $f^t$ that computes the final output of the combiner $\y$.

A robust black-box DAG combiner algorithm, is then executed by tracing the computation through the corresponding DAG $\G$. 
The input to every oracle query is computed from the response of the oracles at the preceding vertices
using the Turing machine $f^v$ associated with the respective vertex $v \in V(\G)$.
The output of the algorithm is given by the output of $f^t$ on the respective inputs.
We assume that the random tape of the intermediate Turing machines are initialized identically to the random tape 
of the combiner Turing machine \todo{argue}.
A robust black-box DAG combiner has to satisfy that the algorithm induced by the DAG description 
needs to be a robust black-box combiner. We formally define robust black-box DAG combiners as follows,
we use $|\prim{P}|$ for primitive $\prim{P}$ to denote the number of implemented algorithms 
and generically name them $(\alg{Alg}{P}^1, \ldots, \alg{Alg}{P}^{p})$ if $|\prim{P}| = p$.

\begin{definition}[Robust $(n;k)$ Black-Box DAG $\prim{P}$-Combiner]\label{def:robust_blackbox_dag_combiner}
	A roubst $(n;k)$ black-box DAG combiner for primitive $\prim{P}$ is a robust $(n;k)$ black-box algorithm $\BBComb{P}$ in the sense of \Cref{def:robust_blackbox_combiner}, i.e. a tuple algorithms $\Paren{\alg{Alg}{P}^1, \ldots, \alg{Alg}{P}^p}$
	where every algorithm $\alg{Alg}{P}^i$ is specified by a tuple of the following shape
	\[
		\Paren*{\G_p, s_p, t_p, \ell_p, \Brace{f_p^{v}}_{v \in V(\G_p) \setminus \{s_p\}}}
	\]
	Such that for all $p \in \prim{P}$, $\G_p$ is a DAG, $s_p$ and $t_p$ are vertices in $V(\G_p)$
	such that $s_p$ has no ingoing edges and $t_p$ has no outgoing edges,
	$\ell_p : V(\G_p) \to [n] \times \prim{P}$ is a vertex labling and $\Brace{f_p^v}_{v \in V(\G_p) \setminus \{s_p\}}$
	are pt. Turing machines. Where, given the tuple,
	the algorithm $\alg{Alg}{P}^p$ is defined as shown in \Cref{fig:dag_combiner}.

By definition, a robust black-box DAG combiner corresponds to a robust black-box combiner.
We also show that for every robust black-box combiner there exists a canonical robust black-box DAG combiner
which is \textit{computationally equivalent} in the sense that the algorithms implemented 
realize equivalent functions. We state this result in the following theorem, 
which we will be using to lead our impossibility proofs over robust black-box DAG combiners instead of robust black-box combiners.\todo{computational equivalence more def?}

\begin{restatable}[Robust $(n;k)$ Black-Box DAG Combiners]{theorem}{dagEquiv}\label{thm:generality_dag_comb}
	For every robust $(n;k)$ black-box combiner in the sense of \Cref{def:robust_blackbox_combiner} there exists a computationally equivalent 
	robust $(n;k)$ black-box DAG combiner in the sense of \Cref{def:robust_blackbox_dag_combiner}.
\end{restatable}

\paragraph{Intuition.}
The idea behind the proof is to take an arbitrary robust $(n;k)$ black-box combiner $\BBComb{P}$
and unroll its computation in a graph consisting of $T(n,\lambda)$ layers
where each vertex on a layer $k$ is connected to all vertices of the preceding layers $i < k$. Each layer $k$ consisting of 
$n|\prim{P}|$ vertices corresponding to the different oracles which can be queried as the $k$'th query.
At every layer $k$ for every vertex the combiner then simulates the Turing machine of $\BBComb{P}$ until 
the $k+1$'the oracle query. Since the Turing machine $f^v$ can however not make any oracle query itself 
it relies on the previous connected vertices to obtain the answer to those oracle queries. 
For the $i$'th query the Turing machine simply uses the output of the correct vertex on layer $i$
to simulate the oracle query. Once we reach the $k$'th query and the query would be to oracle $\O_{(i,j)}$
then we distinguish the case when we are at the correct vertex or not. If the current vertex satisfies 
$c(v) = (i,j)$ then we simply return the query $\mathbf q_v$ resulting in the correct query being made,
otherwise if $c(v) \neq (i,j)$ then we simply return an arbitrary query that meets the expected input format of 
$\O_{c(v)}$. An important nuance is that we need to fix the random tape of the Turing machines $\rho$
since otherwise between simulating the oracle queries at a later point the executions may diverge.\todo{maybe cover more explicitly}

\section{Impossibility of Robust Black-Box VRF-Combiner}

We consider the possibility of combining VRFs in a black-box fashion.
Specifically, we study the possibilities of combining two candidates, at least one of them 
implementing a secure VRF. Such robust $(2;1)$ black-box combiners are the simplest robust black-box 
combiner construction. However the existence of robust $(2;1)$ black-box combiners
immediately give rise to the robust $(n;1)$ black-box combiners, while an impossibility implies 
that there exists no robuts $(n;\lfloor n/2\rfloor)$ black-box combiner. Consequently, 
settling the $(2;1)$ case in either direction extends to a seemingly stronger result.

In this section we present a proof of the impossibility of robust $(2;1)$ black-box VRF-combiners.
At a high level, the proof exploits the fact that the oracles outputs must be used to produce a 
pseudorandom output but at the same time cannot influence the output distribution "too much"
since otherwise if the candidate were the malleable candidate he could allow for two distinct
images to be produced without the verifier being able to tell the difference.
In the proof we make the simplifying assumption that the secret key space 
of all candidates is given by $\SK_i = \bin^{s_i(\lambda)}$ for a function $s_i \in \poly$.
We state the formal statement in the following theorem.

\begin{theorem}[Robust $(2;1)$ Black-Box VRF Combiner]\label{thm:impossibility_21_comb}
	There exists no robust $(2;1)$ black-box combiner as defined in 
	\Cref{def:robust_blackbox_combiner} for the VRF primitive as defined in \Cref{def:vrf}.
\end{theorem}

\paragraph{Intuition.}
Instead of showing the impossibility for the robust $(2;1)$ black-box combiner, we show an impossibility for 
robust $(2;1)$ black-box DAG combiners. The impossibility of a robust $(2;1)$ black-box VRF-combiner 
then follows directly from the equivalence of robust black-box combiners and robust black-box DAG combiners 
in \Cref{thm:generality_dag_comb}.

Now suppose, for a contradiction, that there exists a robust $(2;1)$ black-box DAG VRF-combiner $\BBComb{VRF}$.
Let $\O_1, \O_2$ be candidate schemes, at least one of which implementing a secure VRF.
By \Cref{def:robust_blackbox_combiner}, $\BBComb{VRF}[\O_1, \O_2]$ must implement a secure VRF. 
In particular, since $\BBComb{VRF}[\O_1, \O_2]$ implements a secure VRF, it must be perfectly correct 
and uniquely provable. We derive a contradiction by initializing $\O_1,\O_2$
with specific candidate schemes of which at least one implements a secure VRF,
and then constructing an adversary $\A^{\PSPACE, \O_1,\O_2}$ that breaks the pseudorandomness of 
$\BBComb{VRF}[\O_1, \O_2]$ with non-negligible advantage.

The adversary works by iteratively narrowing down the set of candidate secret keys in the 
pseudorandomness experiment, starting with the secret key space $\SK$, by relying on its PSPACE complete
oracle $\PSPACE$. The filtering works as follows: $\A$ samples a polynomial number of evaluation points
$x_1, \ldots, x_{2s(\lambda)}$ u.a.r. from $\bin^\lambda$. Then uses the evaluation oracle $\O_{eval}$
in the prf security experiment to evaluate the points under the games secret key $\sk^*$ to obtain image-proof pairs
$(y_1, \pi_1), \ldots, (y_{2s(\lambda)}, \pi_{2s(\lambda)})$.
Using the games public key $\pk^*$ the adversary now computes the trace of the combiners verification algorithm on the tuples 
$(\pk^*, x_1, y_1, \pi_1),\ldots, (\pk^*, x_{2s(\lambda)}, y_{2s(\lambda)},\pi_{2s(\lambda)})$ to obtain 
$\tau_1, \ldots, \tau_{2s(\lambda)}$.
The key ingredient is a ppt. Turing machine $\alg{EvalSim}{VRF}$ that takes as input 
a tuple $(\sk,x_i,y_i,\pi_i,\tau_i)$ and returns either $\top$ or $\bot$, satisfying the following properties:

\begin{itemize}
	\item $\alg{EvalSim}{VRF}$ makes no oracle queries to the candidates $\O_1, \ldots, \O_n$
	\item If $\sk = \sk^*$ then $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \top$
	\item If $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x_i) \neq y_i$ then $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \bot$
\end{itemize}

Before elaborating on the construction of $\alg{EvalSim}{VRF}$ we first explain 
how the adversary can use this ppt. Turing machine to break pseudorandomness of $\BBComb{VRF}[\O_1, \O_2]$.
Recall that we require the security properties of the combiner to hold relative to a PSPACE complete oracle
precisely because we want the combiner to derive its security from the candidate oracles (and not implement it itself).
Now, $\alg{EvalSim}{VRF}$ makes no oracle queries yet still only returns $\top$ if a secret key candidate $\sk \in \SK$
\textit{agrees} with the games secret key $\sk^*$ in the sense that on $x_i$ they evaluate to the same image.
Using its PSPACE complete oracle $\PSPACE$ the adversary can now enumerate the entire secret key space $\SK$
and discard any secret key candidate for which there exists a tuple $(x_i, y_i, \pi_i, \tau_i)$
such that $\alg{EvalSim}{VRF}$ returns $\bot$ (strictly speaking, the $\PSPACE$ oracle decides membership queries for PSPACE languages,
we defer these technicalities to the formal proof). Note that $\sk^*$ is never eliminated since 
$\alg{EvalSim}{VRF}(\sk^*, x_i, y_i, \pi_i, \tau_i) = \top$ always and that all other survivors 
satisfy that they evaluate to the same image as $\sk^*$ under $x_1, \ldots, x_{2s(\lambda)}$.
There are two possible cases that can happen after the narrowing has taken place:

If for sufficiently many tuples $(x_i,y_i,\pi_i,\tau_i)$ the number of eliminated candidate secret keys 
is sufficiently large then after $2s(\lambda)$
iterations of filtering we end up with a polynomially sized set $\SK_{cand}$ containing $\sk^*$.
The adversary can then sample a uniformly random secret key $\sk_{cand} \in \SK_{cand}$, 
winning the security experiment if $\sk^* = \sk_{cand}$. This happens with non-negligible probability.

On the other hand if only for a small number of tuples $(x_i, y_i, \pi_i, \tau_i)$ the size of the set of candidate keys 
decreases significantly this means that for many of the remaining secret key candidates, the probability of evaluating to the 
same image than the experiments secret key on uniformly random evaluation points is non-negligible.
In this scenario the adversary proceeds analogously, he samples a uniformly random secret key candidate and 
evaluates the challenge pre-image $x^*$ to compare with the challenge image $y^*$.
Since $\sk_{cand}$ agrees with the expeirments secret key $\sk^*$ with non-negligible probability 
the adversary wins the game with non-negligible advantage.

We now describe the construction of $\alg{EvalSim}{VRF}$ algorithm.
The algorithm simulates the evaluation of $\BBComb{VRF}[\O_1, \O_2]$ by iterating over the 
the vertices in $V(\G_{\alg{Eval}{VRF}})$ in a fixed but arbitrary topological ordering.
At every vertex $v$ it simulates the associated Turing machine $f_{eval}^v$ on the
corresponding inputs to obtain $\mathbf q_v$. 
Oracle queries to $\O_1$ are answered trivially with a fixed response,
this is the case as we will later initialize this oracle with a trivial, uniquely provable and perfectly 
correct oracle that returns fixed values for key generation and evaluation and verifies exactly the fixed image.
For oracle queries to $\O_2$ we distinguish \textit{exposed} queries, which are contained in the verification 
trace $\tau_i$, and \textit{obscure} queries, which are not contained in the verification trace.
The simulator answers the exposed queries with the response contained in $\tau_i$.
Thus the only queries that cannot perfectly be answered are the obscure queries to $\O_2$.

For every obscure query to $\O_2$ the adversary branches its execution for every well-formed responses
of the query (e.g. all possible values in $\Y \times \P$ if the query is to $\O_2$s evaluation algorithm) and
continues the execution for every branch. Finally if for all branches the evaluation of the combiner is $y_i$
$\alg{EvalSim}{VRF}$ returns $\top$, otherwise it returns $\bot$.

Its easy to see that the first and third requirements for the $\alg{EvalSim}{VRF}$ algorithm are met.
By construction $\alg{EvalSim}{VRF}$ makes no oracle queries to candidates.
Assuming that $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x_i) \neq y_i$
then, since we answer all queries to $\O_1$ and the exposed queries to $\O_2$

obscure queries to candidate $\O_2$ such that the execution of 
$\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x_i)$ is simulated perfectly 
and therefore the output is not $y_i$, thus we have $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \bot$.

For the second property, we argue that for the security experiments secret key $\sk^*$
any assignment of responses to obscure queries to candidate $\O_2$ does not change the image produced by the combiner simulation.
Suppose for a contradiction that there exists two different assignments of oracle responses that result in two different 
images $\tilde y \neq \hat y$. We derive a contradiction in three steps. First, we may assume without loss of generality that 
in the evaluation of the robust black-box DAG combiners evaluation algorithm every specific oracle is queried on a specific input 
at most once (\Cref{claim:unique_queries}). Secondly, we construct two oracles $\widehat\O_2, \widetilde\O_2$, possibly not uniquely provable or perfectly correct, which are 
the oracle $\O_2$ remapped on the obscure queries to the two assignments that produce different images $\hat y \neq \tilde y$ respectively.
Third, we turn $\O_1$ into a full VRF by remapping all but a small subset of evaluation points to agree with the secure VRF $\O_2$ (\Cref{lemma:vrfification}).
Since $\widehat\O_2, \widetilde\O_2$ produce different images but only differ on obscure queries not contained in the verification trace 
they are indistinguishable for the combiners verification algorithm. This forces the combiner to violate either unique provability or perfect correctness.

but the output is ignored. Subsequent queries that would depend on that query re-simulate the execution anyway and therefore

Assume that this would change the combiner execution for some query, then this means that the oracle output were not deterministic 
and based on the internal randomness the combiner output changes. By perfect correctness both resulting distinct outputs 
must verify which would violate unique provability.

Additionally we show that given two VF oracles $\O_{\VRF}$ and $\O_{up}$
such that $\O_{\VRF}$ implements a secure VRF and $\O_{up}$ implements a perfectly correct 
and uniquely provable VF we can construct a new oracle $\O_{\VRF}(\O_{up}, \widetilde\SK)$ such that 
$\O_{\VRF}(\O_{up}, \widetilde\SK, \widetilde\PK)$ implements a secure VRF and its evaluation algorithm agrees on all points $(\sk, x)$
with the oracle $\O_{up}$ where $\sk \in \widetilde\SK$ and $\pk\in \widetilde\PK$
if $|\widetilde\SK|, |\widetilde\PK| \in \poly$. Formally:

\begin{lemma}\label{lemma:vrfification}
	Let $\O_{\VRF}$ be a VF oracle that implements a secure VRF in the sense of \Cref{def:vrf}, 
	$\O_{up}$ be a VF oracle that is uniquely provable in the sense of \Cref{def:unique_provability}
	and perfectly correct in the sense of \Cref{def:correctness} such that 
	$\O_{\VRF}$ and $\O_{up}$ are on the same spaces and let $\widetilde{\SK}, \widetilde{\PK}$
	be polynomially bounded subsets of the secret and public key spaces of both oracles.
	There exists an oracle $\O_{mix}$ such that the following properties are satisfied:
	\begin{enumerate}
		\item The evaluation algorithm of $\O_{mix}$ agrees with the evaluation algorithm of $\O_{up}$
			on all secret keys $\widetilde\sk\in\widetilde\SK$, i.e. we have that
			\[
				\forall \widetilde\sk \in \widetilde\SK, \O_{mix}.\alg{Eval}{VRF}(\sk, \cdot) = \O_{up}.\alg{Eval}{VRF}(\sk, \cdot)
			\]
		\item The verification algorithm of $\O_{mix}$ agrees with the evaluation algorithm of $\O_{up}$
			on all public keys $\widetilde\pk\in\widetilde\PK$, i.e. we have that
			\[
				\forall \widetilde\pk \in \widetilde\PK, \O_{mix}.\alg{Vfy}{VRF}(\pk, \cdot, \cdot, \cdot) = \O_{up}.\alg{Vfy}{VRF}(\pk, \cdot, \cdot, \cdot)
			\]
		\item The oracle $\O_{mix}$ implements a secure VRF in the sense of \Cref{def:vrf}.
	\end{enumerate}
\end{lemma}

Note first that it is not sufficient to simply change all of the mappings of the evaluation algorithm 
of $\O_\VRF$ on the points in $\widetilde\SK$ to the output of $\O_{up}$ and the mappings of the verification 
algorithm of $\O_\VRF$ on the points in $\widetilde\PK$ to the output of $\O_{up}$.
Such a construction would indeed not necessarily be uniquely provable or perfectly correct since 
for one we might have not guaranteed that the verification of a newly mapped output succeeds or 
the verification of a previously mapped output rejects and also we need to consider that if two 
secret keys have non-zero probability to be sampled with the same public key, then they both need to 
induce the same mapping $\X \to \Y \times \P$, also this holds for the public key perspective if we 
change the mappings of the verification algorithm.

\begin{proof}[\Cref{lemma:vrfification}]
We begin by introducing a two relations $\sim_\SK \subseteq \SK^2$ and 
$\sim_\PK \subseteq \PK^2$. Intuitively, these relations capture
whether two secret or public keys have a counterpart which could have been 
sampled with both keys. Formally we define the relations $\sim_\SK, \sim_\PK$ as follows:
\begin{align}
	\sk_1 \sim_\SK \sk_2 &\iff \exists \pk \in \PK, \Prob*{
		\begin{aligned}
			(\sk_1, \pk) &\sample \alg{Gen}{VRF}(1^\lambda) \; \land\\
			(\sk_2, \pk) &\sample \alg{Gen}{VRF}(1^\lambda)
		\end{aligned}
	} > 0 \label{eq:sim_sk}\\ 
	\pk_1 \sim_\PK \pk_2 &\iff \exists \sk \in \SK, \Prob*{
		\begin{aligned}
			(\sk, \pk_1) &\sample \alg{Gen}{VRF}(1^\lambda) \; \land\\
			(\sk, \pk_2) &\sample \alg{Gen}{VRF}(1^\lambda)
		\end{aligned}
	} > 0 \label{eq:sim_pk}
\end{align}
We now consider the transitive closure of those relations $\sim_\SK^*, \sim_\PK^*$,
formally defined by $\sim^* = \bigcup_{k \in \N} \sim^k$. The resulting relations 
$\sim_\SK^*,\sim_\PK^*$ are equivalence relations. Given an element $\sk$
we denote its equivalence class under $\sim_\SK^*$ with $[\sk]_{\sim_\SK^*} = \Brace{\sk' \in \SK : \sk' \sim_\SK^* \sk}$,
similarly for an element $\pk$ and the relation $\sim_\PK^*$.
We claim that keys related with the corresponding relation $\sim^*$
must induce the same mapping on their function. We formalize this observation in the following claim,
since its easy to see that it holds we defer the proof to the appendix.

\begin{claim}
	The relations $\sim_\SK^*$ and $\sim_\PK^*$ defined in $\eqref{eq:sim_sk}$ and $\eqref{eq:sim_pk}$
	respectively are equivalence relations, i.e. reflexive, symmetric and transitive.
\end{claim}

Additionally, for secret and public keys we define the function $R_\SK$ and $R_\PK$
respectively as follows. $R$ maps a key to all counterparts with are sampled with that key 
with non-negligible probability.
\begin{align}
	R_\PK(\pk) &= \Brace*{\sk\in\SK : \Prob*{(\sk, \pk) \sample \alg{Gen}{VRF}(1^\lambda)} > 0}\\ 
	R_\SK(\sk) &= \Brace*{\pk\in\PK : \Prob*{(\sk, \pk) \sample \alg{Gen}{VRF}(1^\lambda)} > 0}
\end{align}
Next we define the notion of the closure of a set.
Given a subset of secret $\widetilde\SK$ or public keys $\widetilde\PK$ we define its closure 
$\closure_\SK(\widetilde\SK)$ and $\closure_\PK(\widetilde\PK)$ which are just the union over the equivalence classes 
of all keys in the subsets. We formally define the functions as follows:
\begin{align}
	\closure_\SK(\widetilde\SK) &= \bigcup_{\widetilde \sk \in \widetilde\SK} [\widetilde\sk]_{\sim_\SK^*}\\ 
	\closure_\PK(\widetilde\PK) &= \bigcup_{\widetilde \pk \in \widetilde\PK} [\widetilde\pk]_{\sim_\PK^*} 
\end{align}
Observe that the secret key closure $\closure_\SK(\widetilde\SK)$ for a subset $\widetilde\SK \subseteq \SK$
is the set of secret keys that need to be remapped if we want to remap all of the evaluations on the 
secret keys $\widetilde\SK$ to preserve unique provability and correctness. The same holds for the public key closure.
Now we define the closure for subsets $\widetilde\SK \subseteq \SK$ and $\widetilde\PK \subseteq \PK$
at the same time.
\begin{align}
	\closure_\SK(\widetilde\SK,\widetilde\PK) &= \closure_\SK(\widetilde\SK) \cup \bigcup_{\widetilde\pk \in \closure_\PK(\widetilde\PK)} R_\PK(\widetilde\pk)\\ 
	\closure_\PK(\widetilde\SK, \widetilde\PK) &= \closure_\PK(\widetilde\PK) \cup \bigcup_{\widetilde\sk \in \closure_\SK(\widetilde\SK)} R_\SK(\widetilde\sk) 
\end{align}
We now constuct an oracle $\widetilde\O_{up}$ that interpolates between $\O_{up}$ and $\O_\VRF$.
To be precise we define all of the algorithms of $\widetilde\O_{up}$:
The key generation algorithm is defined to be the function for key generation of 
$\O_\VRF$ while the function for evaluation and verification are defined as follows.
\begin{align}
	\widetilde\O_{up}.\alg{Eval}{VRF}(\sk, x) &= \begin{cases}
		\O_{up}.\alg{Eval}{VRF}(\sk, x) & \text{if } \sk \in \closure_\SK(\widetilde\SK,\widetilde\PK)\\ 
		\O_{\VRF}.\alg{Eval}{VRF}(\sk, x) & \text{otherwise}
	\end{cases}\\ 
	\widetilde\O_{up}.\alg{Vfy}{VRF}(\pk, x, y, \pi) &= \begin{cases}
		\O_{up}.\alg{Vfy}{VRF}(\pk, x, y, \pi) & \text{if } \pk \in \closure_\PK(\widetilde\SK,\widetilde\PK)\\  
		\O_{\VRF}.\alg{Vfy}{VRF}(\pk, x, y, \pi) & \text{otherwise}
	\end{cases}
\end{align}
Note that the properties $1.$ and $2.$ of \Cref{lemma:vrfification} hold by definition of the oracle
since by reflexivity of $\sim_\SK^*$ and $\sim_\PK^*$ we have 
$\widetilde\SK \subseteq \closure_\SK(\widetilde\SK,\widetilde\PK)$ 
and $\widetilde\PK \subseteq \closure_\PK(\widetilde\SK,\widetilde\PK)$.
We show that $3.$ holds by showing the $\widetilde\O_{up}$ is uniquely provable and perfectly correct 
and pseudorandom seperately.

\begin{claim}\label{claim:vrfification_pc_up}
	Let $\O_{up}, \O_{vrf}$ be oracles implementing a uniquely provable VF in the sense of \Cref{def:unique_provability}
	and a VRF in the sense of \Cref{def:vrf} respectively. The oracle $\O_{mix}$ constructed from 
	$\O_{up}$ and $\O_{vrf}$ is perfectly correct in the sense of \Cref{def:correctness}
	and uniquely provable in the sense of \Cref{def:unique_provability}.
\end{claim}

Let $\lambda \in \N$ be arbitrary. For perfect correctness let $(\sk, \pk) \sample \O_{mix}.\alg{Gen}{VRF}(1^\lambda)$, 
let $x \in \bin^\lambda$ be arbitrary and let $(y,\pi) \gets \O_{mix}.\alg{Eval}{VRF}(\sk, x)$. 
We show that $\sk \in \SK_{map}$ if and only if $\pk \in \PK_{map}$, following that, if $\sk \in \SK_{map}$ then 
$(y,\pi)$ verifies by perfect correctness of $\O_{up}$ and if $\sk \notin \SK_{map}$ then $(y,\pi)$
verifies by perfect correctness of $\O_{vrf}$.

We show only $\sk \in \SK_{map} \implies \pk \in \PK_{map}$, the other direction follows from a 
symmetric argument. Assume $\sk \in \SK_{map}$, by definition of $\SK_{map}$ we distinguish the cases 
$\sk \in \closure(\widetilde\SK)$ and $\sk \in \bigcup_{\widetilde\pk \in \closure(\widetilde\PK)} R_\PK(\widetilde\pk)$.
If $\sk \in \closure(\widetilde\SK)$ then together with $\pk \in R_\PK(\sk)$ we get $\pk \in \bigcup_{\widetilde\sk \in \closure(\widetilde\SK)} R_\SK(\widetilde\sk)$
and therefore $\pk \in \PK_{map}$. On the other hand if $\sk \in \bigcup_{\widetilde\pk \in \closure(\widetilde\PK)} R_\PK(\widetilde\pk)$
then for some $\widetilde\pk \in \closure(\widetilde\PK)$ we have $\sk \in R_\PK(\widetilde\pk)$ but since 
$\widetilde\pk \sim_\PK \pk$ and therefore in particular $\widetilde\pk \sim_\PK^* \pk$ we have 
$\pk \in \closure(\widetilde\pk)$, implying $\pk \in \PK_{map}$.

For unique provability, suppose for a contradiction, that there exist two distinct images 
$y_0 \neq y_1$ with corresponding proofs $\pi_0, \pi_1$ such that
$\O_{mix}.\alg{Vfy}{VRF}(\pk, x, y_0, \pi_0) = \O_{mix}.\alg{Vfy}{VRF}(\pk, x, y_1, \pi_1) = 1$.
Now, if $\pk \in \PK_{map}$ then we break the assumed unique provability of $\O_{up}$
and if $\pk \notin \PK_{map}$ then we break the assumed unique provability of $\O_{vrf}$.
We conclude that the constructed oracle $\O_{mix}$ must indeed be perfectly correct 
and uniquely provable.

Next we show that if $\O_{\VRF}$ is pseudorandom then $\O_{mix}$ is also pseudorandom. 
We formulate this statement precisely in the following claim.

\begin{claim}\label{claim:vrfification_prf}
	Let $\O_{up}, \O_{vrf}$ be oracles implementing a uniquely provable VF in the sense of 
	\Cref{def:unique_provability} and a VRF in the sense of \Cref{def:vrf} respectively
	that is $\errtime$-pseudorandom.
	Let $\widetilde\SK \subseteq \SK, \widetilde\PK \subseteq \PK$ be polynomially bounded subsets of 
	the secret and public key space respectively, i.e. $|\widetilde\SK|, |\widetilde\PK| \in \poly$.

\end{claim}

Assume, towards a contradiction, that $\O_{mix}$ is not pseudorandom, i.e. 
that there exists an efficient (ppt.) adversary $\A$ such that $\A$ wins the pseudorandomness

The difference lemma is a classical result in cryptography and states that the difference in probability of 
an event happening can be bounded from above by the probability of a "bad" event happening conditioned on which 
the previous two events have the same probability of happening.
For completeness we state the result but defer the proof to the appendix.
\begin{lemma}[Difference Lemma]\label{lemma:difference_lemma}
	let $W_0,W_1$ and $B$ be events satisfying:
	\[
		\Prob*{W_0 \mid \lnot B} = \Prob*{W_1 \mid \lnot B} 
	\]
	Then we can impose the following bound:
	\[
		\abs*{\Prob*{W_0} - \Prob*{W_1}} \le \Prob*{B}
	\]	
\end{lemma}
By the above observation we can therefore bound the difference in probability over the two games 
by the probability of event $\E$ occuring. Applying a union bound and the definition of the joint closure
we then arrive at the following bound of the adversary $\A$'s advantage.
\begin{align}
	\Adv{VRF}{prf}{\mathcal A, \O_{mix}} &\le \err_{VRF, mix}^{prf} + \Prob*{\sk \in \closure_\SK(\widetilde\SK,\widetilde\PK)}\\

	&\quad + \Prob*{\sk \in \bigcup_{\widehat\pk \in \closure_\PK(\widetilde\PK)} R_\PK(\widehat\pk)} \\
	&\le \err_{\VRF}^{prf} + |\widetilde\SK|\err_\VRF^{prf} + |\widetilde\PK| \err_\VRF^{prf}
\end{align}
We bound the probabilities and arrive at the final bound we show that if the probability were non-negligible

which is a contradiction since we assume $\O_\VRF$ to be pseudorandom.
For the subsequent proofs keep in mind that the probabilities are over the randomly sampled 
secret key. We consider both probabilities seperately,

Hence we can bound $\Prob{\sk \in \closure_\SK(\widetilde\SK)}$ from above by $\err_{VRF,mix}^{prf}|\widetilde\SK|$.

For the bound on $\Prob{\sk \in \bigcup_{\widetilde\pk \in \closure_\PK(\widetilde\PK)} R_\PK(\widetilde\pk)}$ by a similar argument

\end{proof}

Using this result we claim that for a fixed oracle $\O_i$ and any subset of queries 
made during the evaluation algorithm which are not reflected in the trace of the verification execution, we call such 
queries \textit{hidden}, the output of the evaluation algorithm doesn't change for all possible outputs of the oracles.
That is, if we execute the evaluation algorithm and replace every oracle query 
to an algorithm of $\O_i$ with the output in the transcript or any other random output in the support if 
it doesnt occur in the transcript we arrive at the same value for the right secret key $\sk$. 

\begin{claim}\label{claim:hidden_irrelevant}
	Let $\O_1, \O_2$ be uniquely provable and perfectly correct VF oracles and let $S$ be a set of hidden vertices in $G_{eval}$ with queries made to only one oracle.
	Then they are jointly irrelevant to the output of the combiners evaluation algorithm.
	Specifically we can simulate the output of the individual oracle queries by choosing 
	arbitrary elements in the support of the oracles algorithm.
\end{claim}

\paragraph{Proof of \Cref{claim:hidden_irrelevant}}
Assume this were not the case, we follow the topological ordering and initialize the oracle responses 
to those queries with arbitrary outputs in the support. If at one point the output of the combiner changes 
then simply remap the corresponding oracle and make the other oracle a VRF. Subsequently the combiner needs to be 
uniquely provable, perfectly correct and pseudorandom. By perfect correctness we have
\begin{align}
	\BBComb{VRF}[\hat\O_1, \O_2^{\VRF}].\alg{Vfy}{VRF}(\pk, x, \hat y, \hat\pi) = 1\\
	\BBComb{VRF}[\tilde\O_1, \O_2^{\VRF}].\alg{Vfy}{VRF}(\pk, x, \tilde y, \tilde\pi) = 1 \label{eq:correct}
\end{align}
And by unique provability and $\hat y \neq \tilde y$ we have that
\begin{align}
	\BBComb{VRF}[\hat\O_1, \O_2^{\VRF}].\alg{Vfy}{VRF}(\pk, x, \tilde y, \tilde\pi) = 0 \label{eq:unique_provability}\\
	\BBComb{VRF}[\tilde\O_1, \O_2^{\VRF}].\alg{Vfy}{VRF}(\pk, x, \hat y, \hat\pi) = 0 
\end{align}
Now since the oracle $\tilde\O_1$ and $\hat\O_1$ only differ in the evaluations not covered by the 
verification algorithm the execution of the algorithm will be identical, given the input is the same.
This fundamentally contradicts \eqref{eq:correct} and \eqref{eq:uniquely_provable}, we conclude that the 
resulting combiner is either not perfectly correct or uniquely provable.

We define the evaluation simulation $\alg{EvalSim}{VRF}$ that simulates the evaluation 
without invoking any oracle queries. The simulation will simply traverse the evaluation algorithm 
of the DAG combiner. For any oracle query it checks the corresponding transcript $\tau_i$.
If the query is either to oracle $\O_1$ we can honestly answer it with $0$ or in the transcript, 
then we can answer it hoenstly as well. If the query is \textit{obscure} then we branch once for every possible 
assignment of the oracle response which fits the given format, e.g. for a query to eval we branch 
for every answer $(y,\pi) \in \Y \times \P$. The pseudocode for $\alg{EvalSim}{VRF}$ is shown in \Cref{fig:eval_sim}.
In the following we show that this algorithm satisfies a few properties.

\begin{claim}
	Let $\alg{EvalSim}{VRF}$ be the algorithm as described above and in \Cref{fig:eval_sim}
	taking as input a tuple $(\sk, x, y, \pi, \tau)$ containing a secret key, evaluation point, 
	image, proof and a trace of the combiners verification algorithm on 
	$(\pk, x,y,\pi)$ where $\pk$ is the true public key. Then $\alg{EvalSim}{VRF}$ satisfies the following properties.
	\begin{enumerate}
		\item $\alg{EvalSim}{VRF}$ makes no oracle queries
		\item $\alg{EvalSim}{VRF}(\sk, x, y, \pi, \tau) = \top$ if $\sk = \sk^*$
		\item $\alg{EvalSim}{VRF}(\sk, x, y, \pi, \tau) = \bot$ if $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk,x) \neq y$
	\end{enumerate}
\end{claim}

Informally this means that the evaluation simulation will return with $\top$ on a \textit{non-empty} subset of secret keys
which agrees with the true secret key $\sk^*$ on the evaluation of $x$.

The first property holds by construction of $\alg{EvalSim}{VRF}$ the third property also holds by construction and the 
fact that if the evaluation of $\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x) \neq y$ then there exists an assignment 
of the obscure queries such that every oracle query is answered exactly the same as in the execution of the combiner, hence the 
combiner outputs $\bot$. If $\sk = \sk^*$ we need to argue that for every format adhering assignment of the 
oracle responses to the obscure queries, the output doesn't change. Assume towards a contradiction for two assignments of the 
obscure queries the output of the combiner changes from $y_0$ to $y_1 \neq y_0$.
Now we can apply \Cref{lemma:vrfification} to construct a secure VRF from $\O_1$ which agrees with 
the old candidate on all points queried in evaluation and verification, and reassign obscure queries. 
By perfect correctness both outputs $y_0, y_1$ must verify in their respective world, however 
on all oracle queries done by the verification combiner in the two worlds the queries agree exactly 
(since the queries are obscure) and we break unique provability.

Using this simulator $\alg{EvalSim}{VRF}$ we can describe the set of iteratively filtered candidate secret keys as follows.
Let $\{(x_i, y_i, \pi_i, \tau_i)\}_{i \in [2s(\lambda)]}$ be a set of $2s(\lambda)$ tuples containing a uniformly random 
evaluation point $x_i \in \bin^\lambda$, the evaluation of $x_i$ resulting in the tuple $(y_i, \pi_i)$ 
and the transcript of the combiners verification algorithm on $(x_i, y_i, \pi_i)$. The set of candidate keys is defined as:
\[
	\SK_{cand}(x_i,y_i,\pi_i,\tau_i) := \{\sk \in \SK : \alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i)\}
\]
We claim that for any secret key $\sk_{cand} \in \SK_{cand}$, the probability that the secret key 
evaluates to the same output as the evaluation algorithm of the combiner does on a 
uniformly random value $x \in \bin^\lambda$ is overwhelming. We state this result formally in 
the following claim.

\begin{claim}\label{claim:candidate_likely_good}
Let $\SK_{cand}$ be defined as above and let $\{(x_i, y_i, \pi_i, \tau_i)\}_{i \in [2s(\lambda)]}$ 
then we have that for any secret key $\sk^*$ sampled uniformly at random from the intersection of all filtered
candidate sets, i.e. sampled from
\[
	\sk^* \sample \bigcap_{i \in [2s(\lambda)]} \SK_{cand}(x_i,y_i,\pi_i,\tau_i)
\]
The probability that for a uniformly random challenge $x^* \sample \bin^\lambda \setminus \{x_1, \ldots, x_{2s(\lambda)}\}$ 
the black-box combiner instanciated with the correct oracles evaluates to the same image as for the true secret key
is bounded from below by
\[
	\Prob*{\BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk^*, x) = \BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x)} \ge \frac{1}{p(\lambda)}
\]
For $p$ a polynomial in $\lambda$.
\end{claim}

\begin{proof}[\Cref{claim:candidate_likely_good}]
	For a secret key $\sk \in \SK$ we define the number of secret keys $\sk \in \SK$
	for which the evaluation algorithm under $\sk$ on $x$ agrees with the evaluation algorithm 
	under $\sk^*$ on $x$. 
	\[
		\X(\sk) = \abs*{\Brace*{x \in \bin^\lambda : \BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}^y(\sk, x) = \BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}(\sk^*, x)}}
	\]
	We say that a secret key is \textit{unfavorable} if the probability of a uniformly random 
	evaluation point differing in the output is at least $1/2$
	and let $\SK_{unfav} \subseteq \SK$ be the set of unfavorable keys.
	Since we sample the evaluation points $x$ uniformly at random from $\bin^\lambda$
	the probability of the key surviving the filtering step is given by the following:
	\[
		\Prob*{\sk \in \SK_{cand}(x,y,\pi,\tau)} = \frac{\X(\sk)}{2^\lambda}
	\]
	Since the $2s(\lambda)$ evaluation points $x$ are furthermore sampled i.i.d.
	we can bound the probability the a fixed secret key $\sk \in \SK$ is in the intersection of all 
	$2s(\lambda)$ tuples by the following expression:
	\[
		\Prob*{\sk \in \bigcap_{i \in [2s(\lambda)]} \SK_{cand}(x_i,y_i,\pi_i, \tau_i)} = \Paren*{\frac{\X(\sk)}{2^\lambda}}^{2s(\lambda)}
	\]
	We can bound the expected number of unfavorable secret keys that survive $2s(\lambda)$
	rounds of secret key filtering over the randomness of $x_1, \ldots, x_{2s(\lambda)}$
	by applying the union bound:
	\begin{align}
		&\Expect*{\abs*{
			\SK_{unfav} \cap \bigcap_{i \in [2s(\lambda)]} \SK_{cand}(x_i,y_i,\pi_i,\tau_i)
		}} \\
		\le &\sum_{\sk_{unvaf} \in \SK_{unfav}} \Prob*{\sk_{unfav} \in \bigcap_{i \in [2s(\lambda)]} \SK_{cand}(x_i,y_i,\pi_i,\tau_i)}\\ 
		\le &\sum_{\sk_{unvaf} \in \SK_{unfav}} \prod_{i \in [2s(\lambda)]} \Prob*{\sk_{unfav} \in \SK_{cand}(x_i,y_i,\pi_i,\tau_i)}\\ 
		\le &\sum_{\sk_{unvaf} \in \SK_{unfav}} \prod_{i \in [2s(\lambda)]} \frac{\X(\sk)}{2^\lambda}\\ 
		\le &\sum_{\sk_{unvaf} \in \SK_{unfav}} \prod_{i \in [2s(\lambda)]} \frac{1}{2}\\ 
		\le &\frac{2^\lambda}{2^{2s(\lambda)}}
	\end{align}
	Which for general polynomials $s(\lambda) > \lambda$\todo{add assumption?} is negligibly small.
	We can now use a simple Markov bound to show that the probability of a bad key surviving the filtering 
	is negligibly small. Note that the expected number of surviving unfavorable secret keys is by 
	definition non-negative and therefore we have that the probability of all keys filtered is given by the 
	following expression:
	\[
		\Prob*{\abs*{\SK_{unfav} \cap \bigcap_{i \in [2s(\lambda)]} \SK_{card}(x_i,y_i,\pi_i,\tau_i)} \ge 1} \le \frac{2^\lambda}{2^{2s(\lambda)}}
	\]
	To bound the final probability simply condition on the event that no bad key survives.
	Let $\E$ be the event that $|\SK_{unfav} \cap \bigcap_{i \in [2s(\lambda)]} \SK_{cand}(x_i, y_i,\pi_i,\tau_i)| = 0$
	and let $\mathcal F$ be the event that $\BBComb{VRF}[\O_1,\O_2].\alg{Eval}{VRF}^y(\sk^*,x^*) = \BBComb{VRF}[\O_1,\O_2].\alg{Eval}{VRF}^y(\sk,x^*)$. 
	Note that if $\lnot \E$ holds we know that only \textit{favorable} keys survive and therefore the probability of 
	the same image is at least $1/2$.
	\begin{align}
		\Prob*{\mathcal F} &= 1 - \Prob*{\lnot\mathcal F \mid \E} \Prob{\E} - \Prob*{\lnot\mathcal F \mid \lnot \E}\Prob*{\lnot \E}\\ 
		&\ge 1 -  \Prob{\lnot \mathcal F \mid \E} - \Prob*{\lnot \E}\\ 
		&\ge 1 - \tfrac{1}{2} - \tfrac{2^\lambda}{2^{2s(\lambda)}} \\ 
		&\ge \tfrac{1}{2} - \tfrac{2^\lambda}{2^{2s(\lambda)}}
	\end{align}
	Which concludes this proof.
\end{proof}

Now we define the following two languages $\mathcal L_{cand}, \mathcal L_{size}$ as follows.
\begin{align}
	\mathcal L_{cand} &:= \Brace*{
		\Paren*{\rho, i, b, \{(x_i, y_i, \pi_i, \tau_i)\}_{i \in [2s(\lambda)]}} : 
		\rank\rho{\bigcap_{j \in [2s(\lambda)]} \SK_{cand}(x_i,y_i,\pi_i,\tau_i)}_i
		= b} \\ 
	\mathcal L_{size} &:= \Brace*{
		\Paren*{m, \Brace*{\Paren*{x_i,y_i,\pi_i,\tau_i}}_{i \in [2s(\lambda)]}} : 
		\abs*{\bigcap_{j \in [2s(\lambda)]}\SK_{cand}(x_i,y_i,\pi_i,\tau_i)} \le m
	}
\end{align}
We show that $\mathcal L_{cand}$ and $\mathcal L_{size}$ are in PSPACE and can therefore be decided by 
the PSPACE complete oracle. The adversary will first use binary search over $m$ to recover the size of the 
candidate set $\SK_{cand}$ and then pass use the language $\mathcal L_{cand}$ to recover a uniformly 
random candidate secret key $\sk_{cand}$.
Formally stated in the following two claims.

\begin{claim}\label{claim:lang_pspace}
	$\mathcal L_{cand} \in \PSPACE$ and $\mathcal L_{size} \in \PSPACE$.
\end{claim}

To proof \Cref{claim:lang_pspace} we need to provide Turing machines $\mathcal M_{cand}, \mathcal M_{size}$
that decide whether an arbitrary element is member of the language $\mathcal L_{cand}$ and $\mathcal L_{size}$
respectively such that space used by $\M_{cand}$ and $\M_{size}$ is bounded from above by functions polynomial in their input size.
$\M_{cand}$ iterates over the keys in canonical ordering, for every secret key $\sk \in \SK$ iterate over all $i \in [2s(\lambda)]$
and for every $i$ verify whether $\alg{EvalSim}{VRF}(\sk, x_i, y_i, \pi_i, \tau_i) = \top$.
If that holds for every $i$ then increment a counter. If we would increment the counter but the 
value of the counter is $\rho$ then check the $i$'th bit of the candidate is equal to $b$.

The algorithm $\M_{size}$ requires works similarly. We iterate over all secret keys $\sk \in \SK$
and keep a counter to count the number of secret keys that pass every filter.
For every secret key candidate $\sk$ we iterate over all $i \in [2s(\lambda)]$
and increment the counter if for all values $\alg{EvalSim}{VRF}(\sk, x_i,y_i,\pi_i,\tau_i) = \top$.
The algorithm only needs space for the counter in $\O(s(\lambda))$ and the execution of $\alg{EvalSim}(\sk,x_i,y_i,\pi_i,\tau_i)$
which is also polynomial. This concludes the proof of \Cref{claim:lang_pspace}.

We can now describe the distinguisher $\mathcal D$ for the pseudorandomness game as follows:
$\mathcal D$ first samples $2s(\lambda)$ evaluation points $x_i$ uniformly at random from $\bin^\lambda$,
then he uses the evaluation oracle of the pseudorandomness security experiment $\O_{eval}$
to evaluate the points and obtain $(y_1, \pi_1), \ldots, (y_{2s(\lambda)}, \pi_{2s(\lambda)})$.
Subsequently he computes the trace of the combiners verification algorithm $\tau_i$ on $(x_i, y_i, \pi_i)$.
Using binary search and at most $2s(\lambda)$ many queries to its PSPACE complete oracle it can recover 
the size of the set of candidate secret keys $\SK_{cand}$ using the language $\mathcal L_{size}$.
He then samples a uniformly random number $\rho \in [|\SK_{cand}|]$ then then bit-for-bit, again 
using $2s(\lambda)$ many queries recovers a the $\rho$'th candidate key in canonical ordering from $\SK_{cand}^{\{(x_i, y_i, \pi_i, \tau_i)\}_{i \in 2s(\lambda)}}$.
He then samples a uniformly random challenge $x^* \sample \bin$, 
checking that $x^* \neq x_i$ and returns the secret key candidate $\sk_{cand}$ in the state and $x^*$.

In the second stage then then gets $\sk_{cand}, x^*$ and $y^*$. He simply recomputes $y' \gets \BBComb{VRF}[\O_1, \O_2].\alg{Eval}{VRF}(\sk_{cand}, x)$
and returns $0$ if $y^* = y'$ and $1$ otherwise.

\section{Strong Robust Black-Box Combiners}

Having ruled out the possibility of combining VRFs, VUFs, wVRFs even for statistical notions of correctness 
and unique provability and all oracles pseudorandomness we need to make an even stronger assumption to allow for combiners to exist.
We will assume that all candidates satisfy unique provability. This is a strong assumption since 
unique provability is one of the main properties of VRFs which distinguishes VRFs from PRFs
which admit simple robust $(n;1)$ black-box combiner constructions. 
We note that unique provability is generally required to be perfect for good constructions,
meaning that most existing constructions come with rigorous mathematical proofs that assert their 
unique provability. Examples of this are ECVRF and Lattice VRFs, which are the most 
famous constructions of VRFs.\todo{change}

As previously mentioned, PRFs admit a simple robust $(n;1)$ black-box combiner
which simply xors the outputs of all PRF candidates. We show that this construction 
can be extended to VRFs by simply computing the trace of the evaluation algorithms trace 
and providing this as a proof. The existence of such combiners is formalized in the following lemma.

\begin{lemma}[Strong Robust $(n;1)$ Black-Box VRF Combiners]\label{lemma:strong_robust_black_box_combiners}
	There exist robust $(n;1)$ black-box combiners in the sense of \Cref{def:robust_blackbox_combiner}
	for the VRF primitive \Cref{def:vrf} if we assume that all candidates are uniquely provable 
	and perfectly correct.
\end{lemma}

\section{Discussion}

There are different ways to combine VRFs, for both unique provability and key-homomorphism 
they cannot be combined in a black-box fashion if we want to preserve properties such as 
unpredictability and therefore also randomness. On the other hand we manage to construct a 
robust black-box combiner that combines unbiasabile VRFs under guaranteed unique provability 
for all candidates. We find that the black-box combination of information theoretic properties 
generally seems hard if other properties such as unpredictability need to be preserved. 
While the class of all robust black-box combiners initially seems to be very broad we show that 
we can capture all polynomially bounded combiners using the notion of a robust black-box DAG combiner,
which allows a more systematic analysis of possible constructions by abstracting a graph structure 
in the computation executed by the implemented algorithms. We have not considered 
possible combiner constructions for stronger relaxations, such as computational unique provability 
or correctness with error, this is mainly because the resulting construction only offer weak 
guarantees that are insufficient for practical applications.

\paragraph{Extensions.}
We show that there exists no robust $(n;\lfloor n/2\rfloor)$ black-box combiner for the VRF primitive,
naturally we wonder whether an impossibility can be shown for robust $(n;n-1)$ black-box VRF-combiners
which eliminates the possibility of combining VRFs if even one candidate is not guaranteed to be secure.
We believe this statement to be true. Additionally it would be interesting to study how to strongly combine 
the notion of unbiasable VRFs, another advanced notion of VRFs introduced in \cite{}.

Having shown that general notion of combiners on VRFs even with relaxed requirements on the security
